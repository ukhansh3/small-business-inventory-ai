# 수용 기준

> 우선순위 2위. AC 번호는 기획서 9절·API 명세 6절과 같다(AC-3은 커뮤니티 제외로 없음). 테스트 이름에 AC 번호를 붙인다.
> 판정 데이터는 `data/` 고정 데이터와 테스트용 시각(`X-Debug-Now`, 테스트에서는 함수 인자 `now`)을 쓴다.

## 시나리오 1 — 상추 검색 (P0)
사장님이 '상추'를 입력 → 양·급함·받는 방식을 고름 → 결과 목록 → 전화하기.

| AC | 조건 | 정상 결과 | 완료 판정 |
|---|---|---|---|
| AC-5 | '상추' 입력 | `ask` 순서 qty_kg → urgency → fulfillment. '상추 2키로 급해요'면 첫 질문이 fulfillment | API 테스트(저장된 응답) |
| AC-1 | 원하는 양 1kg, 판매처 A 최소 2kg | A 없음. 2kg이면 A 있음 | 단위 테스트 |
| AC-2 | 배달, 내 위치 원천동, 판매처 B 배달 동네 [우만동] | B는 `no_delivery` 묶음, '배달 안 됨' | 단위 테스트 |
| AC-4 | C 가격·단위(1박스 4kg)·출처·확인일 모두 / D 확인일 없음 | C '1박스(4kg) 15,000원 · 가게 안내 · 11월 3일 확인', '(kg당 약 3,800원)' / D '가격 정보 없음' | 단위 테스트(문자열 일치) |
| AC-7 | 21:00(한국), 판매처 E 07:00~20:00, 급함 now | E는 `unavailable_time`, '지금은 닫힘 · 내일 07:00' | 단위 테스트 |
| AC-8 | 월 10:00, F 마지막 입고 오늘 07:00 / G 월 15:00 입고 | F '오늘 07:00 입고됨' / G '오늘 15:00 입고 예정' | 단위 테스트 |
| AC-9 | 같은 묶음 4곳 | 입고 → 거리 → kg당 가격 → 이름 순 | 단위 테스트 |
| AC-12 | 조건에 맞는 곳 0 | total 0, 바꿀 조건 한 줄 | 단위 테스트 |
| AC-6 | 데이터에 없는 값 | 응답의 모든 판매처 값이 데이터에 있음. 없는 값은 '정보 없음' | 단위 테스트(응답 값 ⊂ 데이터) |
| AC-13 | 전화하기 | 예시 데이터면 '예시 번호' 안내, `tel:`을 열지 않음. 기록 1건(P1) | 컴포넌트 테스트 / 수동 |

## 오류·예외 공통
| 상황 | 기대 |
|---|---|
| 빈 문장·201자 이상 | 400 `INVALID_INPUT`, 입력창 안내 |
| 없는·끝난 세션 | 404/409, 앱이 새 세션으로 다시 보냄 |
| 비활성 품목으로 `/search` | 400 `ITEM_NOT_ACTIVE` |
| 기록(Supabase) 실패 | 사용자 응답은 정상 |
| 네트워크 끊김 | '연결이 끊겼어요' + 다시 시도 |
| 운영 배포에서 `X-Debug-Now` | 무시 |
| 사진이 너무 큼(줄인 뒤 4MB 이상)·이미지 아님 | 400 `INVALID_INPUT`, "사진을 다시 골라 주세요" |
| 사진 읽기 실패(AI) | 503 `AI_UNAVAILABLE`, "가격을 글로 적어 주세요" 안내 |
