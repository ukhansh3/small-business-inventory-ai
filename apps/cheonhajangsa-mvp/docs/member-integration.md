# 회원 기능 통합 — 2026-11-08

## 기준

- 지도·검색·AI: 민혁 브랜치 `4979c31` 구현과 기존 API를 유지한다. 최신 `a3c1589`와의 차이는 README뿐이다.
- UI: 승인된 천하장사 시안의 흰 배경·주황색·모바일 하단 5탭 구조.
- 회원 기능: 기존 `docs/features/` 및 `docs/api/openapi.yaml` 초안을 구현 기준으로 사용한다.
- 사용자 승인: 닉네임 / 구매처 질문·가격 제보·거래 경험 / 삭제는 상태 전이 / 신고는 수동 검토.

## 구현

| 영역 | 연결 |
|---|---|
| 지도·AI | 기존 `useStores`, `useAssist`, 검색·사진 진단·조건 수정·전화·상세 |
| 계정 | 이메일 가입·로그인·메일 확인·세션 갱신·로그아웃 |
| 커뮤니티 | 분류별 목록·페이지 이동·현재 페이지 검색·상세·작성·수정·삭제·댓글·좋아요·저장·신고 |
| 저장 | 내 업체 저장·해제·목록, 저장 게시글 조회·해제 |
| 프로필 | 내 이메일·닉네임·메일 확인 상태, 닉네임 수정, 위치·저장 이동 |

회원 API는 JWT를 Supabase Auth `getUser`로 검증하고 소유자 ID를 토큰에서 결정한다. 기기 ID만으로 회원 기능에 접근할 수 없다. 서버 service key는 클라이언트에 전달하지 않는다. 네이티브 세션은 Expo SecureStore, 웹은 main의 기존 방식처럼 localStorage를 사용한다.

`/api/v1/auth/session`, `/auth/signup`, `/auth/refresh`, `/auth/logout`과 `/me/profile`, `/me/saved-vendors`, `/community/*`를 추가했다. 기존 지도 익명 기기 API와 충돌하지 않는다.

지도 ID는 `v_001` 및 공공데이터 문자열 ID이므로 저장 API의 vendorId는 uuid로 제한하지 않는다. 저장 목록에서 현재 정보를 조회할 수 없는 업체는 정보를 지어내지 않고 확인 불가 상태로 표시한다. 자동 가격 알림은 구현 범위에 넣지 않았다.

## DB 적용 필요

읽기 전용 확인 결과 현재 Supabase에는 `chj_community_posts`, `chj_saved_vendors`가 없다(`404 PGRST205`). 다음 파일을 해당 프로젝트의 SQL Editor에서 실행해야 한다.

`supabase/migrations/202611080001_member_features.sql`

기존 테이블을 변경하지 않고 5개 회원 테이블을 새로 만든다. RLS를 켜고 anon/authenticated 직접 접근을 막는다. 서버만 검증 후 접근한다. 실제 DB 적용 전까지 커뮤니티·저장 API는 503을 반환하며 성공처럼 표시하지 않는다.

## 미완·비범위

- 실제 계정 가입·메일 인증·로그인·복수 사용자 데이터 검증은 아직 수행하지 않았다.
- DB migration은 파일만 작성했고 원격 적용하지 않았다.
- 신고는 pending 상태로 접수하며 별도 운영자 신고 검토 화면은 추가하지 않았다.
- Google/Kakao OAuth·탈퇴·비밀번호 재설정은 키와 보존 정책 결정 전 제외한다.
- main의 업체 등록·검토 흐름은 이번 회원 탭과 자동으로 연결하지 않는다. 지도 원천 ID와 등록 DB의 UUID 계약이 다르므로 별도 정합화가 필요하다.
- 민혁의 네이티브 지도·사진 선택은 기존 웹 전용 한계가 그대로 있다. 앱스토어 배포 완료를 의미하지 않는다.
- GitHub push·merge·배포는 수행하지 않았다.

## 검증 상태

- 타입 검사 통과, 회원 권한 테스트 10개를 포함한 151개 테스트 통과.
- 수정한 회원·UI 파일의 ESLint 통과. 전체 기존 파일의 린트 정리는 별도이며 이번 통과 결과에 포함하지 않는다.
- 웹 export 통과. 클라이언트 번들에서 서버 비밀키 문자열 검출 0건.
- 로컬 화면 HTTP 200, 인증 없는 회원 API 401 확인.
- Android export는 Hermes 컴파일러 종료 코드 6으로 실패. 설치·기기 실행 검증은 미완료다.
- 실제 Supabase 회원 테이블 적용과 복수 사용자 E2E는 미완료다.

## 로컬 실행 명령

```bash
npm ci
npm run dev:api
npm run web -- --port 8082
```

`.env.local`의 `EXPO_PUBLIC_API_BASE_URL`은 로컬에서 `http://localhost:8787`로 설정한다. 배포는 같은 출처를 사용하므로 비워 둔다. 서버 키를 `EXPO_PUBLIC_*`에 넣지 않는다.

현재 대화의 미리보기는 기존 서버 충돌을 피하기 위해 웹 8084, API 8791 포트로 실행했다. 프로세스 환경변수로만 설정했으며 사용자 원본 env 파일은 변경하지 않았다.
