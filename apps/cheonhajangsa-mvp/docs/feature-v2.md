# 기능 명세 v2: 단가 진단 + 지도 (2026-11-04)

> `mvp-scope.md` 4절(v2 범위)의 상세. 이 문서와 mvp-scope가 어긋나면 mvp-scope가 이긴다.
> 결정 출처: 2026-11-04 사용자 결정(아래 0절), 멘토링 1차 전사본, 인터뷰 로그 1~13.

## 0. 왜 하나: "우리 걸 왜 써야 하나"
- 멘토링 1차: 핵심 가치를 "훨씬 뾰족하게", AI는 "깔고 가는" 기능이 아니라 질문 하나로 정보를 얻게 해야 엣지가 된다. 진짜 가치는 쿠팡·마트에 없는 **동네 가게 가격처럼 인터넷에 없는 정보**.
- v1(상추 찾기)의 한계: 데이터를 우리가 손으로 넣은 예시뿐이라 "잘 찾아 주는 앱"에 머문다.
- v2의 답: **영수증·결제내역 한 장으로 "내가 비싸게 사는지"를 알려 주고(단가 진단), 그 값이 쌓여 인터넷에 없는 동네 시세가 된다.** 동네 가게는 공공데이터로 지도에 깔아 둔다(지도).

### 근거
| 근거 | 출처 | 내용 |
|---|---|---|
| 영수증 단가 비교가 거래처 교체를 낳음 | 로그 3 용주방 | 앞가게 사장과 폐유 단가 얘기 중 실제 영수증 단가가 다른 것을 발견하고 업체 교체 |
| 적정가는 전화를 돌려야 앎 | 로그 8 호카고 | "모르는 분야는 적정가를 여러 군데 전화해야 안다", 단가를 숫자로 기억 |
| 온라인 가격과 이미 비교 | 로그 2 닭갈비 | 식자재마트·쿠팡 등 4곳 비교, 쿠팡 가격 알림 |
| 동네 가격은 인터넷에 없음 | 로그 10 샐러디 | "가격이 인터넷에 다 안 나와 비교가 번거로움" |
| **미검증 가정** | — | 사장님이 영수증·결제내역을 보관하고 사진으로 올릴 것. 인터뷰 질문지(set-02)에 '매입명세 사진' 요청이 있었으나 결과 기록 없음. 발표에서 미검증으로 밝힌다 |

### 사용자 결정 (2026-11-04)
| 항목 | 결정 |
|---|---|
| 입력 | 입력창 하나, 문 세 개: 재료 한 마디(찾기+동네 시세) / 가격 한 줄(견적 진단) / 사진(영수증·모바일 영수증·플랫폼 결제내역·상품 화면) |

| 지도 화면 | 첫 화면이 지도 + 아래 목록(네이버·카카오맵 방식). 지도는 카카오맵 |
| 일정 | 둘 다 11/11 발표까지 |

## 1. 사용자 흐름

### 1.1 첫 화면 (S-10 지도 홈)
```
┌──────────────────────────┐
│ [예시 데이터 띠]           │
│ ┌──────────────────────┐ │
│ │ 상추, 가격, 사진 📷    │ │ ← 입력창 하나(지도 위에 떠 있음)
│ └──────────────────────┘ │
│        카카오맵           │
│   ● 판매처 핀(확인·예시)   │
│   ○ 공공데이터 가게 핀     │
│   ◎ 내 위치              │
├──────────────────────────┤
│ ▔▔  목록 시트(끌어올림)    │ ← 대화·되묻기·결과·진단이 이 시트에 나온다
│ 근처 식자재 가게 24곳      │
└──────────────────────────┘
```
- 처음 열면 내 위치 중심으로 영통·팔달 가게 핀과 목록이 보인다. 목록은 가까운 순.
- 입력창에 무엇을 넣느냐에 따라 시트 내용이 바뀐다(아래 1.2~1.4). 지도 핀은 시트 목록과 같은 가게를 보여 준다.
- 핀을 누르면 시트가 그 가게 카드로 올라온다. 확인된 판매처는 지금처럼 전화하기·자세히, 공공데이터 가게는 "가격·재고 미확인 · 공공데이터" 표시와 [카카오맵에서 보기].

### 1.2 문 1 — 재료 한 마디: "상추"
- 지금 흐름 그대로(되묻기 → 결과). 결과는 시트 목록 + 지도 핀으로 같이 보인다.
- **결과 위에 동네 시세 한 줄**: "이 동네 상추 kg당 3,500~4,200원 · 중간 3,800원 · 6건 기준(예시 포함)". 표본이 3건 미만이면 "아직 비교할 정보가 적어요".

### 1.3 문 2 — 가격 한 줄: "상추 2키로 만원 부르던데"
- AI가 품목·양·금액을 뽑는다(새 도구 `check_price`). 사진이 없는 신규 사장님의 주 경로.
- 진단 카드: "kg당 5,000원 · 동네 중간 3,800원보다 32% 비싼 편" + 더 싼 곳 최대 3곳(거리순) + [이 조건으로 찾기].
- 양이나 금액이 없으면 진단하지 않고 "양과 금액을 같이 적어 주세요. 예: 상추 2kg 1만원"(11/05 구현 중 변경, C16).

### 1.4 문 3 — 사진: 영수증·결제내역·상품 화면
- 입력창 📷 → 사진 찍기/고르기 → 앱이 줄여서(긴 변 1600px, JPEG, 3MB 이하) 보낸다.
- 서버가 AI(이미지 읽기)로 줄마다 품목·수량·단위·금액을 뽑는다. 개인정보 칸(카드번호, 이름, 주소, 사업자번호, 주문번호)은 **뽑지 않는다.**
- 진단 카드(줄마다): 상추 줄은 kg당 환산·판정·더 싼 곳. 다른 품목 줄은 "아직 상추만 비교해요" + [요청 남기기].
- 카드 아래 [이 가격 동네 시세에 보태기(가게 이름 없이)] — 누르면 동의로 기록.
- 영수증이 아닌 사진이면 "영수증이나 결제내역 사진을 올려 주세요".

## 2. 규칙 (R-16~R-22)
| 번호 | 규칙 |
|---|---|
| R-16 | kg당 가격 = 금액 ÷ (수량 × 단위 kg). 단위 kg을 알 수 없으면(예: '1봉', '1단'인데 무게 없음) **비교하지 않고** "단위를 알 수 없어요". 지어내지 않는다(R-02) |
| R-17 | 배송비가 따로 있으면 줄 금액에 넣지 않고 따로 표시한다(온라인 결제내역) |
| R-18 | 동네 시세 = 같은 품목의 (a) 가격 있는 판매처 판매 정보 + (b) 동의한 구매 기록(최근 30일, 영통·팔달). 표본 3건 미만이면 시세를 만들지 않는다. 표시는 최저~최고, 중간값, 건수, 예시 포함 여부 |
| R-19 | 판정: 내 kg당 가격이 중간값보다 15% 넘게 높으면 "비싼 편", 15% 넘게 낮으면 "싼 편", 그 사이는 "보통". 15%는 가정(인터뷰 "유의미하게 낮아야 바꾼다"에서 시작, 리허설 후 조정 가능) |
| R-20 | 더 싼 곳 = kg당 가격이 내 가격보다 낮은 판매처, 거리순 최대 3곳. 영업 판정은 지금 검색과 같다 |
| R-21 | 사진 원본과 AI가 읽은 원문 글자는 저장하지 않는다. 저장 칸은 고정 목록(5절)뿐 |
| R-22 | 공공데이터 가게는 이름·주소·업종·좌표만 보여 주고 출처와 기준일을 표시한다. 가격·입고·번호를 붙이지 않는다. 판매처(확인·예시) 목록과 섞일 때도 구분 표시 |

## 3. AI
| 항목 | 내용 |
|---|---|
| 글 입력 | 기존 도구 2개(`search_vendors`, `give_notice`) + 새 도구 `check_price {item_id, qty_kg, amount_won}`. 없는 값은 null |
| 사진 | 새 호출(이미지 1장 + 품목 후보) → 도구 `report_purchase {doc_type, seller_type, purchased_on, delivery_fee_won, lines[{raw_name, item_id, qty, unit, unit_kg, amount_won}]}`. strict 스키마 |
| doc_type | `paper_receipt` / `mobile_receipt` / `platform_order` / `product_page` / `invoice` / `not_receipt` |
| seller_type | `local_store` / `food_mart` / `online_platform` / `unknown` |
| 모델 | 기본 `claude-haiku-5-5`(이미지 읽기 정확도가 evals 목표 미달이면 상위 모델 비교). 사진 응답 대기 `AI_VISION_TIMEOUT_MS`(기본 20초) |
| 저장된 응답 모드 | 글 '상추 2키로 만원 부르던데'는 저장된 응답이 있다. 사진은 저장된 응답이 없어 AI 실패와 같은 안내(가격 한 줄로) |
| 검증 | 서버가 다시 검증: 금액·수량 양수, item_id는 사전에 있는 값, unit_kg 없으면 비교 안 함 |
| 실패 | 시간 초과·형식 오류 → "사진을 읽지 못했어요. 다시 찍거나 가격을 글로 적어 주세요"(문 2로 안내) |
| 한도 | 사진도 AI 호출로 센다(기존 하루 500회·세션 6회) |
| evals | 합성 영수증·결제내역 이미지 10장 이상(종이·모바일·쿠팡형·상품 화면·영수증 아님). 목표: 상추 줄 금액·수량 추출 정확도 90% 이상, 지어낸 금액 0, 영수증 아님 판별 100% |

## 4. 지도
| 항목 | 내용 |
|---|---|
| 지도 | 카카오맵 JavaScript SDK(웹). 앱 키는 공개용 JavaScript 키(`EXPO_PUBLIC_KAKAO_JS_KEY`), 카카오 개발자 콘솔에 배포·로컬 도메인 등록 |
| 공공데이터 | 소상공인시장진흥공단 상가(상권)정보 경기 파일(기준일 2026-09-30, 사용자가 `data/`에 둠, 업로드 제외). 수원시 영통구·팔달구에서 **채소/과일 소매업(G20506) 전부 + 슈퍼마켓(G20404) 중 이름에 마트·식자재·도매·공판장·청과·야채·채소가 든 곳**(11/05 사용자 결정. 슈퍼마켓 전체는 그릇점·전자석유 등이 섞여 제외, 편의점·정육점 제외) → `data/public_stores.json` 295곳. 11/05 사용자 결정으로 이름에 삼성전자·매점·카페·이마트24·편의점이 든 곳 제외(회사 안 매점·편의점 22곳) → **273곳**(팔달 173, 영통 100 / 채소·과일 151, 슈퍼마켓 122). 만드는 법 `scripts/build-public-stores.ts`, 검사 `npm run check:data`(AC-27) |
| 핀 | 확인된 판매처(진한 색), 예시 판매처(예시 표시), 공공데이터 가게(흐린 색), 내 위치 |
| 목록 시트 | 지도 화면 영역의 가게를 가까운 순으로. 검색·진단 결과가 있으면 그 결과로 바뀌고 지도도 결과 핀만 강조 |
| 성능 | 영통·팔달 대상 가게 수 확인 후 결정. 수백 곳이면 화면 영역 안 핀만 그린다 |
| 기존 화면 | 대화·되묻기·결과·상세·위치 고르기는 그대로 쓰되 시트 안에 넣는다. 위치 프리셋 중 우만동(팔달구)은 범위 안이 된다 |

## 5. 저장 (DB 0004)
`chj.price_checks`: id, device_id, session_id, source(`text`/`photo`), doc_type, seller_type, purchased_on, delivery_fee_won, ai_mode, model, created_at
`chj.price_check_lines`: check_id, line_no, item_id(null 가능), qty_kg, amount_won, price_per_kg(null 가능), comparable, verdict, shared(동의 여부), created_at
- 저장하지 않는 것: 사진, AI가 읽은 원문 글자(raw_name 포함), 가게 이름, 카드·주문·개인 정보. raw_name은 응답으로만 돌려주고 저장하지 않는다.
- 시세 계산은 `shared=true`인 줄만.

## 6. API
| ID | 경로 | 하는 일 |
|---|---|---|
| API-01 확장 | `POST /assist/turns` | 글 입력에서 AI가 `check_price`를 고르면 `type: "price_check"` 응답 |
| API-15 | `POST /price-checks` | 사진 진단. `{image:{media_type, data(base64)}, session_id?, location_id}` → 진단 결과 |
| API-16 | `PATCH /price-checks/{id}` | `{share: true}` 시세에 보태기 동의 |
| API-17 | `GET /market?item_id&location_id` | 동네 시세(R-18). API-01·02 결과에도 `market` 칸으로 같이 실림 |
| API-18 | `GET /stores?bbox=&category=` | 지도용 가게(판매처 + 공공데이터) |
요청 본문 상한: 사진 3MB 이하(base64로 약 4MB, Vercel 함수 본문 한도 4.5MB).

## 7. 범위 밖 (이번에 하지 않음)
상추 외 품목 시세, 판매처가 직접 가격 올리기, 리뷰·평점, 카카오맵 장소 정보(전화번호 등) 가져오기, 지도에서 길찾기, 네이티브 앱 지도, 사진 여러 장 한 번에, 영수증 원본 보관.

## 8. 위험
| 위험 | 대응 |
|---|---|
| 일정(11/11, 1인) | 단가 진단 서버 → 화면 → 공공데이터 → 지도 순. 11/9 리허설 전에 고정. 지도가 늦으면 지도는 목록 위 고정 지도(시트 없이)로 줄인다 |
| 카카오 키·공공데이터 승인 대기 | 키·파일이 늦으면 지도는 예시 판매처만으로 먼저 만들고 공공데이터는 나중에 붙인다 |
| 이미지 읽기 오류 | 사진마다 '이렇게 읽었어요' 줄 목록을 보여 주고, 틀리면 가격 한 줄로 다시 입력 |
| 비교 기준이 예시 | 시세 한 줄과 진단 카드에 "예시 데이터 포함"을 늘 표시 |
| 실제 가게 표시 | 공개 정보만, 출처·기준일 표시, 가격·재고 미확인 명시(R-22) |
