## 1. 발표 10분 구성 (시연 7분 + 질의 3분)

중간평가② 안내의 시연 순서와 동료평가 문항을 그대로 따른다.

| 순서 | 시간 | 보여 줄 것 | 동료평가가 보는 것 |
|---|---|---|---|
| ① 대상 사용자와 문제 | 1분 | 문제 한 문장, 성공의 정의 (2절·3절) | 최종 목표를 판단할 비교 기준 |
| ② 핵심 시나리오 | 5분 | 실제 입력부터 결과까지 실행 (4절) | 문제 해결 흐름이 실제로 작동하는가 |
| ③ 최종 목표 | 1분 | 정량·정성 목표와 측정 방법 (6절) | 목표가 문제와 성공의 정의에 맞는가 |
| 질의 | 3분 | 예상 질문 대비 (9절) | — |

동료평가 5점 조건: 실제 입력부터 결과까지 끊김 없이, 부가 기능이 아니라 핵심 흐름에 집중. 고정값을 쓴 부분은 시연 중에 밝힌다(밝히면 최소 4점).

## 2. 문제 한 문장

> 개업 초기 사장님은 동네 채소가게가 어디 있고 언제 신선한 물건이 들어오는지 알 방법이 주변 사람뿐이라, 재료가 급할 때 발품을 팔거나 가까운 마트·쿠팡에서 산다.

정보 격차가 원인이고, 급한 재료 조달이 그 격차가 드러나는 장면이다.

| 문장의 부분 | 인터뷰 근거 |
|---|---|
| 동네 업체를 알기 어렵다 | "모든 건 업체가 뭐가 있는지를 일단 보는 게 좀 어렵죠. 판단하는 건 어차피 그렇게 어렵진 않아" (인터뷰 8 호카고, 08:05) |
| 인터넷에 없다 | "가격이 인터넷이라고 업체마다 다 나오는 게 아니기 때문에" (인터뷰 10 샐러디, 질문 5) |
| 주변 사람에게 묻는다 | "옆집 사장님, 오래된 사장님한테 어디가 물건이 좋고 가격이 덜 싸냐고 물어보고 한 게 한 3년 전에" (인터뷰 9 하남돼지집, 10:33) |
| 개업 초기에 발품을 판다 | "한 10여 곳은 가봤지" (인터뷰 9 하남돼지집, 11:33) |
| 개업 초기에 비싸게 쓴다 | "제가 초기에는 좀 비싸게 쓰고 있었거든요" (인터뷰 8 호카고, 08:55) |
| 재료가 급할 때가 실제로 있다 | "밖에서 사온다 하는 거는 한 일주일에 한 번 정도" (인터뷰 3 용주방, 05:32) |
| 급하면 쿠팡·다른 곳으로 달려간다 | "제가 알아서 쿠팡에서 사던가 아니면 다른 데 달려가서 해야 되는데" (인터뷰 8 호카고, 02:20) |
| 채소는 신선도가 중요하다 | "모자라게 시켜서 차라리 못 파는 게 낫지" (인터뷰 4 최가네칼국수, 04:07) |

대상이 아닌 사람: 본사가 품목을 정해 주는 프랜차이즈, 품목마다 이미 아는 업체가 있는 오래된 가게.

## 3. 성공의 정의

사장님이 앱 결과만 보고 **전화할 가게 한 곳을 고를 수 있으면** 문제를 해결한 것이다. 주변 사람에게 묻거나 발품을 파는 대신, 앱이 그 역할을 한다.

## 4. 핵심 시나리오 (시연 5분)

**주인공**: 아주대 앞에서 한 달 전 개업한 국밥집 김사장(가상). 점심 손님이 몰려 상추가 떨어졌다. 동네 채소가게를 모른다.

| 단계 | 사장님이 하는 것 | 화면 | 연결된 규칙 |
|---|---|---|---|
| 1 | 앱을 열고 '상추'라고 입력 | 입력창, 상단에 '예시 데이터' 표시 | — |
| 2 | AI가 되묻는다: "얼마나 필요하세요?" → '2kg' 선택 | 선택지 버튼(1kg / 2kg / 5kg / 1박스) | 최소 주문량보다 적게 원하면 그 가게는 빠진다 |
| 3 | "언제까지 필요하세요?" → '지금 바로' 선택 | 선택지(지금 바로 / 오늘 안 / 내일) | 지금 영업 중이고 오늘 입고된 곳을 위로 |
| 4 | "직접 가지러 가세요, 배달이 필요하세요?" → '직접' 선택 | 선택지(직접 / 배달) | 직접이면 가까운 순, 배달이면 배달 지역 밖 가게에 '배달 안 됨' 표시 |
| 5 | AI가 고른 조건을 보여 주고 검색 | '상추 2kg · 지금 바로 · 직접' 요약 + 업체 목록 | 조건을 눌러 고치면 AI 없이 다시 검색 |
| 6 | 결과 카드를 본다 | 가게 이름, 거리(도보 몇 분), 전화번호, 입고 시간('매일 오전 7시 입고 · 오늘 입고됨'), 가격(보조: '1kg 4,000원 · 가게 안내 · 11월 3일 확인') | 가격은 출처·확인일이 다 있을 때만 |
| 7 | 한 곳을 골라 '전화하기' | 전화 앱 연결 | — (성공의 정의) |
| 8 | (범위 밖) '대파도 있어요?' | "아직 상추만 준비돼 있어요. 다른 채소가 필요하시면 알려 주세요" + [요청 남기기] | 없는 정보를 지어내지 않는다. 요청은 '확장 요청 비율' 측정에 쓴다 |

결과 카드에서 강조하는 순서: **위치·거리·연락처 → 입고 시간(신선도) → 가격(보조)**.

## 5. AI가 하는 일과 하지 않는 일

**흐름**: 한 마디 입력 → AI가 빠진 조건(양·언제·직접/배달)을 선택지로 되묻기 → AI가 업체 검색 도구 호출 → 코드가 규칙대로 거르고 정렬 → 결과

| 구분 | 내용 |
|---|---|
| AI가 하는 일 | 사장님 말에서 품목·양·급함·수령 방식을 뽑는다. 빠진 것만 되묻는다. 검색 도구를 호출한다 |
| 코드가 하는 일 | 최소 주문량 제외, 영업 중·입고 여부, 거리·배달 지역, 정렬. 반드시 지켜야 할 규칙은 AI가 아니라 코드가 강제한다(강의 6) |
| AI가 하지 않는 일 | DB에 없는 가게·가격·입고 시간을 지어내지 않는다. 상추 외 품목은 "아직 없음"으로 안내한다. 검색과 무관한 질문에는 도구를 부르지 않는다 |
| 시연에서 밝힐 것 | AI 응답을 저장된 응답으로 바꾼 부분이 있으면 그 자리에서 말한다 |

과목 요구와의 연결: 되묻기와 도구 호출은 '도구 편입', 상추 판매처 정보 검색은 'RAG', AI 정확도 측정은 'evals'에 들어간다.

## 6. 최종 목표 (12/09 최종평가까지)

### 정량 목표

| 지표 | 목표값 | 측정 방법 |
|---|---|---|
| 확장 요청 비율 | 테스트한 사장님 5명 중 3명 이상이 상추 외 다른 채소를 요청 | 개업 초기 사장님 5명이 앱을 직접 쓰고, '요청 남기기' 기록과 대화 메모로 센다. 2명 이하면 품목 선택과 가치를 다시 본다 |
| AI 조건 정확도 | 90% 이상 | 평가 케이스 20건 이상에서 AI가 뽑은 조건(품목·양·급함·수령 방식)이 정답과 맞는 비율. 키워드 규칙 추출기와 비교 |
| 지어낸 업체·가격 | 0건 | 같은 평가에서 DB에 없는 가게·가격·입고 시간을 말한 건수. 1건이라도 있으면 실패 |
| 범위 밖 거절 | 100% | 상추 외 품목, 검색과 무관한 질문에 도구를 부르지 않고 안내한 비율 |

멘토의 성공 신호: "좋은데요. 혹시. 그런데 대파는 없나요?" 이렇게 가면 좋은 거죠(멘토링 39:41).

### 정성 목표

테스트한 사장님이 앱 결과만 보고 "여기에 전화하겠다"며 가게 한 곳을 고르고, 고른 이유로 **거리나 입고 시간**을 말하면 달성으로 본다.

### 가장 위험한 가정과 확인 계획 (교수 평가 3-3 보완)

> 가정: 아주대 앞 상추 판매처의 입고 시간·연락처·가격을 우리가 직접 모을 수 있다.

멘토 조언대로 초기 데이터는 우리가 발품으로 채운다(배민 초기 전단지 사례, 멘토링 34:03). 이것이 안 되면 서비스가 성립하지 않는다.

| 항목 | 계획 (실행 전에 확정) |
|---|---|
| 평가 단위 | 방문한 가게 1곳 |
| 판정 규칙 | 입고 시간과 연락처를 모두 확인하면 '확보'. 가격은 덤 |
| 합격선 | 방문 4곳 중 3곳 이상 확보. 2곳 이하면 데이터 수집 방식을 다시 정한다 |
| 방법 | 발표 이후 팀원 2명이 아주대 앞 채소가게 방문, 동의 문구를 읽고 기록 |

## 9. 질의 대비

| 예상 질문 | 답의 방향 |
|---|---|
| 식봄·쿠팡과 뭐가 다른가 | 그곳은 이미 아는 물건을 주문하는 곳이다. 동네 채소가게처럼 인터넷에 없는 가게의 위치·입고 시간을 보여 주는 곳은 없다. 사장님은 급할 때 근처 어디로 달려갈지를 모른다 |
| 데이터는 어떻게 모으나 | 처음에는 우리가 직접 발품으로 넣는다(7절 계획). 사장님이 쓰기 시작하면 판매처에 "여기서 사장님들이 찾는다"며 직접 올리게 한다 |
| 왜 상추 하나인가 | 한 품목에서 쓸모가 확인되면 넓힌다. 확장 요청 비율로 확인한다 |
| 예시 데이터 아닌가 | 맞다. 화면에 표시했다. 발표 이후 현장 확인 계획과 합격선은 7절 |
| 품질은 사람마다 다르지 않나 | 그래서 주관적 평가 대신 입고 시간·당일 입고 여부라는 사실만 보여 준다 |

## 10. 만드는 방식 (확정)

### 결정
| 항목 | 결정 | 이유 |
|---|---|---|
| 앱 | 새 Expo 앱, 웹 우선 | 같은 코드가 브라우저와 휴대폰 앱으로 돈다. '앱 MVP'이면서 강의실 Windows PC는 설치 없이 링크로 시연한다 |
| 화면 크기 | 휴대폰 화면 폭(약 430px)을 브라우저 가운데에 | 앱처럼 보이게 |
| 서버 | AI 호출용 서버 함수 1개(Vercel) | Claude API 키를 브라우저에 두지 않는다 |
| 데이터 | 앱 안 `data/` 폴더의 데이터 파일(판매처·판매 정보·품목·위치, 상세는 개발기획서 3절) | DB·권한·키 없이 시연·테스트·evals가 같은 파일을 쓴다 |
| 배포 | Vercel 링크 하나 | 강의실 PC와 11/11~18 다른 팀 사용 주간에 같은 링크 |
| 위치 | 팀원 앱과 분리된 내 폴더 | 팀원 개발과 섞이지 않게. 나중에 둘 중 나은 쪽을 고른다 |

### 쓰지 않는 것 (팀 저장소에 있지만 이 기획에 필요 없음)
로그인·회원가입, 업체 등록·운영자 검토, 사진 업로드, 커뮤니티, 카카오 지도, 팀 Supabase DB, 기존 웹 프로토타입(`apps/cheonhajangsa`), Expo Go 실행 방식, Android 미리보기 APK.

### 데이터 파일을 써도 되는가
된다. 강의 5는 테스트용 고정 데이터(fixture)를 파일로 두고 경로와 버전을 기록하라고 한다. 데이터가 코드와 같은 폴더에 있으면 골든 케이스·evals·시연이 같은 값을 쓰므로 결과를 재현하기 쉽다. 팀원 개발과도 겹치지 않는다. 실제 서비스 단계에서 DB로 옮기는 것은 발표 이후 과제로 둔다(현장 확인 결과가 들어갈 자리).

### 데이터 파일의 칸
가게 id, 이름, 종류(채소가게·식자재마트·시장 점포), 주소, 좌표, 전화번호, 영업시간, 입고 시간, 오늘 입고 여부, 최소 판매량, 배달 가능 여부·지역, 가격·단위·출처·확인일, `example: true`
