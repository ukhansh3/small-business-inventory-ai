# 모바일 개발 가이드

2026-10-28 사용자가 Android·iPhone 공통 모바일 앱 전환을 요청했다. 이 문서와 ADR-007이 기존 Next.js 사용자 화면 고정 규칙을 대체한다. 나머지 제품 계약과 개인정보·증거 규칙은 유지한다.

## 폴더 역할

- apps/mobile: 실제 Android/iOS 사용자 화면과 모바일 권한·내비게이션.
- apps/cheonhajangsa: 기존 웹 프로토타입 보관, 카카오 지도 전용 HTTPS 페이지, 향후 서버용 코드. 기존 phone 프레임은 새 네이티브 앱 화면이 아니다.
- docs/database: 운영자 검토·품목·필수 가격에 대한 DB 설계 설명. 실제 DB 변경과 구분한다.

## 모바일 스택

React Native, Expo SDK 58, Expo Router, TypeScript, pnpm, Zod를 사용한다. View/Text/Pressable/TextInput/ScrollView를 사용하고 HTML·CSS·브라우저 전역에 의존하는 화면 코드를 모바일로 복사하지 않는다. 공용 색상과 컴포넌트는 src/components/ui.tsx에서 관리한다. 태블릿·회전 화면에서는 콘텐츠 최대 너비와 유동 레이아웃을 사용한다.

기존 shadcn/ui, Tailwind DOM 컴포넌트와 Next.js 라우팅은 모바일 화면에 적용하지 않는다. 네이티브 지도 SDK로 전환하는 경우 양 플랫폼 호환성과 키 등록 변경을 별도로 검증한다. 현재는 기존 카카오 JS SDK만 지도 전용 WebView로 격리한다.

## 데이터·권한

업체 직접 등록, 품목·가격 필수, 운영자 확인 후 공개가 사용자 결정이다. 현재 앱의 업체 데이터는 명시된 가상 자료이며, 승인된 실데이터가 아니다. 모바일 폼 검증은 편의를 위한 것이며 서버의 소유권·승인 검사와 RLS를 대체하지 않는다. API/DB DTO는 별도 승인·구현 후 연결한다.

Kakao REST 지오코딩, Supabase 관리자 키, OpenAI 호출은 서버에만 둔다. 기기 위치는 버튼을 누를 때만 요청하고 거부해도 탐색할 수 있어야 한다. 현재 앱은 위치를 DB에 저장하지 않는다.

## 팀 협업

최신 main에서 개인 브랜치를 만들고 apps/mobile에서 frozen-lockfile로 설치한다. 웹 폴더가 아닌 모바일 폴더의 README 명령을 따른다. 각자 .env.example을 .env.local로 복사하고 공개 지도 URL만 설정한다. 앱 전체를 Vercel에 올려 네이티브 배포를 대신하지 않는다. Vercel은 지도 전용 페이지나 API 서버를 호스팅할 수 있다.

기능 브랜치·PR·리뷰 규칙을 유지한다. 승인되지 않은 스키마와 공개 계약은 임의 변경하지 않는다. 향후 실제 서버·DB 통합은 이번 UI 전환과 구분한다.

## 확인 기준

린트·타입·단위 테스트와 Android/iOS 번들을 확인한다. 설치 파일 컴파일, 실기기 검증, 스토어 배포를 별도로 기록한다. 지원 최소 OS, 키보드, 안전 영역, Android 뒤로 가기, iOS 상세 닫기, 화면 회전, 접근성 글자 크기, 오프라인 목록, 지도 타임아웃과 재시도를 확인한다. 실행하지 않은 실기기·기종 검증을 완료했다고 쓰지 않는다.
