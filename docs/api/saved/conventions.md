# API-SAVED — 공통 규약

**상태:** S-01~S-10 UX 승인, API 경로·물리 설계는 **제안 / 미구현**.
- 접두사 `/api/v1`; HTTPS/JSON; 금액은 KRW 숫자 원, 날짜는 ISO 8601.
- 서버 검증된 시연 세션 자격을 사용한다. 앱에 로그인 화면은 없으나, **무인증 공개 쓰기 API는 금지**. 구현 시 API 요청의 사용자/세션 검증 방식은 공통 시연 세션 설계에 따름.
- 본인 시연에서만 쓰기/조회. 실제 운영업체 공개 DTO는 읽기 전용.
- `demo_session_id`, `actor_id`를 사용자가 요청 본문으로 전달하더라도 소유권 증명으로 신뢰하지 않는다.
- 서버 반환 오류 구조는 기존 `vendor-api.ts`와 맞춤: `{ "error": { "code": "...", "message": "...", "requestId": "..." } }`.
- `saved_at`은 서버 생성. 목록 페이징 cursor는 안정적 정렬; 기본 limit 20, 최대 50은 **기술 제안**.
- 다른 세션 데이터/비공개 게시글/미공개 업체 구분은 동일하게 `NOT_FOUND` 처리하여 존재 여부를 감춘다.
- 동시 요청 처리: PUT/DELETE 멱등. 과거 탭 요청 응답이 최신 북마크 상태를 덮지 못하게 mutation sequence/client invalidation 적용.
- `GET /saved`는 표시 가능한 항목의 요약 정보만 반환하며 원본 콘텐츠 보안/공개 검증을 매 요청 시 수행한다.
- 시연 초기화는 여러 feature가 공유하는 `demo_sessions` 수명주기에서 처리. `saved` 자체가 전체 시연을 초기화하지 않음.
