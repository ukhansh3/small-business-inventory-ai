# FEAT-SEARCH-001 — 지도 기반 업체 탐색

- 상태: **부분 확정 + 설계 초안**
- 우선순위: P0
- 승인된 UI 결정: **지도 중심 홈(A), 핀 선택 시 하단 카드, 위로 펼쳐 목록**
- 승인된 핀 정책: **검색 전 업체명만; 단일 일치 품목은 품목·가격; 2개 이상 일치하면 `일치 품목 N개`만**
- 승인된 핀 클러스터링 정책: **업체 밀집 시 업체 수로 클러스터 표시, 확대 시 개별 업체 핀으로 분리; 클러스터 탭 시 해당 영역으로 지도 확대(Q13 A)**
- 승인된 지역 재검색 정책: **지도 조작 완료 후 `이 지역 검색` 버튼 표시, 탭한 경우에만 현재 지도 가시 영역(bounds)으로 재검색**
- 승인된 결과 조회 정책(Q11 A): **지도는 마지막으로 적용한 가시 영역의 전체 일치 업체 대상으로 핀/클러스터를 구성, 하단 목록은 20개씩 추가 로딩**
- 승인된 초기 시트(Q14 A): **첫 실행 시 접힌 검색 결과 요약바, 핀 선택 시 업체 카드로 전환**
- 승인된 목록 기본 정렬(Q12 A): **마지막으로 적용한 지도 화면의 중심에서 거리 가까운 순**
- 관련 화면: `docs/ui/screens/vendor-search.md`
- 관련 API: `docs/api/vendor-search/get-vendors.md`, `get-vendor-detail.md`
- 관련 DB: `docs/database/vendor-search.md`
- 기존 수용 기준 연결: AC01, AC02, AC03, AC05, AC06, AC08, AC12, AC15, AC16

## 1. 목적
사용자가 지도 기준 위치에서 공급업체를 찾고, 업체·품목·가격·배송 조건을 검토한 뒤 업체 상세 화면으로 이동한다. 실제 업체의 승인된 공개 정보와 시연 데이터의 출처를 오인하지 않도록 한다.

## 2. 승인된 핵심 사용자 흐름
1. 앱을 실행하면 로그인 화면 없이 지도 탐색 홈으로 진입하며, **하단 시트는 접힌 검색 결과 요약바**로 시작한다(Q14 A 승인; 인증 구현은 별도 명세).
2. 사용자가 검색어·카테고리 등 조건을 지정하고 지도에서 업체 핀을 확인한다. 지도를 드래그하거나 확대·축소한 뒤에는 `이 지역 검색` 버튼이 나타난다. 새 지역 데이터는 버튼을 누른 경우에만 조회한다.
3. **핀 탭 → 해당 업체 하단 카드 노출.** 곧바로 상세 페이지로 이동하지 않는다.
4. 하단 카드를 위로 스와이프하면 현재 검색결과의 업체 목록이 펼쳐진다.
5. 하단 카드의 `업체 상세 보기` 버튼을 누르면 업체 상세 화면으로 이동한다. **펼친 목록의 업체 행을 탭했을 때의 동작은 Q15에서 결정**하므로 자동 상세 이동을 확정하지 않는다.
6. 결과가 없거나 지도 로딩이 실패해도 이유를 명확히 표시하고 재시도 또는 목록 사용 경로를 제공한다.

## 4. 현재 서버 기능과 연결
- 실제 공개 업체: `GET /api/v1/vendors` (좌표/반경/검색어/카테고리/offset; Bearer 필요 — **현재 코드**)
- 상세: `GET /api/v1/vendors/{id}` (승인 업체 1건; Bearer 필요 — **현재 코드**)
- 기본 조회 20건 단위, 거리 오름차순 + 업체 ID 기준 안정 정렬.
- 시연 모드의 인증/데이터 결합은 위 API 구현과 다름. 별도 설계·테스트 필요.

## 5. 검색어에 따른 핀 레이블 규칙 (사용자 승인 + 미결정 분리)
- 검색어가 **없으면** 각 핀에는 **업체명만** 표시한다. 가격, 대표 품목, 임의 최저가를 노출하지 않는다.
- 검색어가 **품목명을 검색하고 특정 업체에서 일치 품목이 1개**라면 해당 품목의 명칭·수량/단위와 **그 품목의 가격**을 표시한다. 값은 실제 API/명시적 시연 소스의 필드에서 가져온다.
- 검색어가 **업체명에만 일치**하고 일치하는 품목은 없다면 핀에는 해당 업체명만 표시한다. 임의 품목 가격은 표시하지 않는다.
- 검색어에 **한 업체의 품목이 2개 이상 일치**하면 핀은 **`일치 품목 N개`**로 표시한다. 핀에는 개별 품목 가격을 쓰지 않고 첫 품목·최저가·대표 가격을 임의 선정하지 않는다.
- 여러 품목이 일치한 핀을 선택하면 **선택한 업체의 하단 카드에 일치한 모든 품목의 이름·규격·수량/단위·가격을 항목별로 보여준다.** 카드 내용이 길어지면 내부 스크롤을 제공한다. 카드 내 상세 보기 버튼은 유지한다.
- 품목 매칭은 검색어 trim 및 대소문자 무시 부분 문자열 검색을 기준으로 하며, 업체명만 일치한 것은 품목 개수에 포함하지 않는다. API의 전체 `items[]`를 무조건 일치 목록으로 표시하지 않는다.
- 검색어·카테고리·검색 결과가 바뀌면 표시된 핀 레이블과 하단 카드가 **같은 검색 상태**에서 갱신된다. 이전 검색 가격을 새로운 검색 결과에 남기지 않는다.
- `GET /api/v1/vendors` 응답에는 업체의 전체 공개 품목이 담길 수 있다. 그러므로 **검색에 일치한 품목**은 모바일에서 현재 검색어와 품목명을 대조하거나 별도 승인된 API 필드를 통해 판단하며, `items[0]`을 일치 품목으로 취급하지 않는다.

## 5-1. 지도 클러스터링 정책 (Q-SEARCH-10 A 확정)
- 클러스터링은 **조회된 서로 다른 업체 ID**를 대상으로 한다. `일치 품목 N개`는 한 업체의 품목 개수이고, 클러스터 숫자 `N`은 클러스터에 포함된 **업체 수**이므로 서로 혼동하지 않는다.
- 업체가 밀집해 개별 핀을 읽거나 탭하기 어려운 줌에서는 인접 업체를 하나의 숫자 클러스터로 표시한다.
- 지도 확대 시 밀집이 풀리면 클러스터를 개별 업체 핀으로 분리한다. 개별 핀에서는 기존 승인된 검색어/가격/복수 품목 레이블 규칙을 동일하게 적용한다.
- 클러스터는 다수 업체의 가격을 평균·합계·대표가로 표시하지 않는다.
- 클러스터링은 지도 **표시 방식**이며, 검색 지역 적용은 여전히 `이 지역 검색` 탭 시에만 일어난다. 확대·축소로 클러스터 형태가 변하는 것은 새 서버 검색 요청과 구분한다.
- **Q11 A 확정:** 클러스터는 **현재 목록 페이지**가 아니라 마지막으로 적용한 가시 지도 영역 내 **전체 일치 업체 ID**를 대상으로 한다. 목록은 동일 조건으로 20개씩 추가 로딩한다. 현행 20건 조회만으로 전체 클러스터를 구현한 것으로 간주하지 않으며 새로운 데이터 제공 계약을 먼저 설계한다.
- **Q13 A 확정:** 클러스터 탭 시 군집 영역으로 중심 이동·확대하고 현재 클러스터를 재계산한다. 검색된 기존 데이터의 지도 표시만 변화하며 `이 지역 검색` 버튼이 나타난다. **이 탭만으로 검색 API 호출·업체 카드 자동 선택·목록 강제 펼침은 하지 않는다.**
- 미정: 클러스터 반경/임계값, 구체적 확대 레벨 및 이동 애니메이션, 대량 결과 성능 한계.

## 6. 예외 / 사용자 상태
- 위치 권한 거부: 기본 지도 위치 또는 마지막 정상 위치 사용, 안내 표시; 실제 현재 위치라고 표시하지 않는다.
- 결과 0건: 빈 상태 메시지와 검색어/위치/필터 변경 유도.
- 서버 오류: 오류 노출; 실제 데이터 오류를 성공한 가상 검색으로 대체하지 않는다.
- 지도 장애: 업체 목록은 계속 접근 가능해야 한다.
- 재검색으로 선택 업체가 결과에서 사라짐: 선택 카드를 닫고 현재 결과로 UI 동기화한다(구현 제안).
- 요청 지연: 이전 결과를 최신 결과인 것처럼 표시하지 않는다.
- 지도 이동 후 새 검색 전: 지도 시점과 적용된 검색 기준이 달라질 수 있음을 UI가 구분한다.
- `이 지역 검색` 요청 실패: 오류·재시도 버튼을 표시하며 과거 결과를 새 지역 결과로 오인하게 하지 않는다.

## 7. 수용 테스트 초안
- **SEARCH-AC01** 핀을 누르면 상세 화면으로 이동하지 않고 선택 카드가 열린다.
- **SEARCH-AC02** 하단 카드를 위로 스와이프하면 결과 목록이 펼쳐지고, 다시 내리면 지도 영역이 확대된다.
- **SEARCH-AC03** 목록에 로드된 업체 ID는 동일 검색 조건의 지도 전체 업체 집합의 부분집합이어야 한다. 목록을 끝까지 로딩하면 (좌표 유효성 등 계약된 예외를 제외하고) 전체 검색 결과 ID가 일치해야 한다.
- **SEARCH-AC04** 카드의 상세 버튼은 선택된 업체 ID로 상세 화면을 연다.
- **SEARCH-AC05** 검색/필터 변경 시 현재 선택 상태와 목록이 새 결과에 맞게 갱신된다.
- **SEARCH-AC06** null 가격/배송비가 0원/무료로 표시되지 않는다.
- **SEARCH-AC07** 검색 오류와 검색 결과 없음이 서로 다른 UI로 표시된다.
- **SEARCH-AC08** 지도 장애 시에도 목록과 상세 이동이 가능하다.
- **SEARCH-AC09** 게스트 시연이 실제 승인 업체/사용자 데이터를 변경하지 않는다(별도 인증·시연 설계 완료 후 검증).

- **SEARCH-AC10** 검색어가 비어 있을 때 핀에 품목 가격이 나타나지 않고 업체명만 표시된다.
- **SEARCH-AC11** 검색어가 한 업체의 단일 품목명에 일치하면 해당 품목의 가격과 규격을 표시하고 다른 품목 가격을 표시하지 않는다.
- **SEARCH-AC12** 검색어가 업체명에만 일치하는 경우 업체명만 보인다.
- **SEARCH-AC13** 검색어 변경 시 핀의 품목/가격 레이블이 갱신되고 과거 레이블이 남지 않는다.

## 12. 전체 지도 업체 + 20건 목록 (Q-SEARCH-11 A 승인)
- 검색 키를 `마지막 적용된 bounds + 검색어 + 카테고리 + 출처`의 조합으로 취급한다. 지도 전체 집합과 목록 페이지를 **동일 검색 키**로 가져온다.
- 지도 데이터: 검색 키에 일치하는 **모든 공개 업체**의 식별자·유효 좌표·핀 표시용 필요한 정보를 확보한 뒤, 중복 ID 없이 클러스터링한다. 클러스터 숫자는 실제 포함 업체 개수다.
- 목록 데이터: **20개씩** 추가 로딩한다. 목록의 `더 보기`는 지도에 누락된 핀을 추가하는 동작이 아니라 동일 결과에서 다음 목록 행만 가져오는 동작이다.
- 목록을 20건만 로딩한 상태에서도 지도는 전체 결과 집합을 표시해야 한다. 초기 목록 길이와 전체 지도 업체 개수는 달라도 오류가 아니다.
- `이 지역 검색`으로 검색 키가 변경되면 지도 전체 집합·목록 1페이지·선택 업체 상태를 그 키에 맞게 동기화한다. 이전 요청의 지연 응답이 새 결과를 덮지 않는다.
- 사용자가 지도를 조작만 했을 때는 기존 `appliedBounds`의 결과로 클러스터를 재배치할 수 있지만, 확대·축소만으로 새로운 지역 API를 호출하지 않는다.
- **미확정 기술 계약:** 클러스터용 경량 업체 조회/페이지 전체 수집/서버 집계 가운데 선택, 최대 결과 개수·범위, 조회 지연 시 UI. 전체 결과가 누락된 상태를 완전한 결과로 표현하지 않는다.

## 13. Q12 A — 목록 기본 정렬 (2026-11-04 사용자 승인)
- 하단 업체 목록은 **검색을 마지막으로 적용한 지도 가시 영역의 중심점**을 기준으로 업체별 거리를 계산해 **오름차순(가까운 순)** 정렬한다. 사용자의 현재 GPS 위치가 기준은 아니다.
- 해당 검색 조건에서 매칭된 **전체 공개 업체 집합**에 대해 먼저 일관된 거리순 순서를 정하고, 목록에서 **20개 단위**로 순차 표시한다. 페이지마다 다른 중심점으로 정렬하지 않는다.
- `이 지역 검색`을 누르기 전 지도 이동·확대·축소만으로 현재 목록 재정렬이나 새 목록 API 호출을 하지 않는다. 사용자가 버튼을 눌러 새 검색을 **성공적으로 적용한 때**에만 기준 중심점을 바꾸고 목록을 첫 페이지부터 갱신한다.
- 거리 동률에는 기존 구현의 업체 ID 순 안정 정렬을 재사용한다(현재 API 계약에 이미 존재하는 보조 정렬). 새로운 가격순/관련성순 모드가 승인된 것은 아니다.
- **SEARCH-AC35:** 같은 조건으로 검색한 업체 A(중심에서 0.4km), B(1.2km), C(2.5km)는 A→B→C 순으로 표시한다. 단위 표기는 예시다.
- **SEARCH-AC36:** 45건 매칭 시 1~20, 21~40, 41~45건은 모두 같은 중심 기준 거리순의 연속 구간이고 중복이 없다.
- **SEARCH-AC37:** 사용자가 지도를 이동만 했을 때 기존 목록 순서와 API 호출은 유지되고, `이 지역 검색`을 눌러 새 결과 적용 후에만 정렬 기준점이 갱신된다.
- **기술 미결정:** 실시간 데이터 변경 중 여러 페이지를 일관되게 읽는 스냅샷/커서 전략, 과대 지도 영역·결과 처리 상한, 가격순 비교식·조건 미확정.

## 14. 클러스터 탭 수용 기준 (Q13 A 승인)

- **SEARCH-AC39:** 클러스터 탭 및 그에 따른 지도 중심 이동/확대만으로 **새로운 업체 검색 HTTP API 요청은 발생하지 않는다.** 지도 조작 완료 뒤 `이 지역 검색` 버튼이 나타난다.

## 15. Q14 A — 초기 하단 요약바 / 핀 선택 카드 (사용자 승인)
- 앱을 처음 열면 `PEEK_SUMMARY`를 기본 상태로 사용한다. 고정 높이 전체 목록이나 업체 1~2개의 미리보기를 기본 노출하지 않는다. 지도가 최대한 넓게 보이도록 한다.
- 초기 검색 결과가 도착하면 요약바에 업체 전체 개수와 목록 펼치기 안내를 표시한다. **전체 개수는 동일 조건의 전체 고유 업체 수**이며, 첫 20건을 전체 건수처럼 표시하지 않는다. 결과 수가 확정되지 않은 로딩/오류 상태는 별도로 안내한다.
- 개별 핀 탭 시 시트 내용을 `SELECTED_CARD`로 바꾸고 해당 업체 정보(일치 품목·규격·가격 포함)를 보여준다. 상세 화면 이동은 `업체 상세 보기` 버튼에서만 확정되어 있다.
- 접힌 요약바를 위로 스와이프하거나 명시적 펼치기 접근성 버튼을 누르면 `EXPANDED_LIST`를 열어 거리순 20건부터 확인한다.
- **SEARCH-AC42:** 첫 진입에서 업체 카드가 자동 선택되지 않고 접힌 결과 요약바가 보인다.
- **SEARCH-AC43:** 개별 핀 1개 탭 → 해당 업체 카드로 바뀌며 곧바로 상세 화면으로 이동하지 않는다.
- **SEARCH-AC44:** 요약바 위로 스와이프 → 거리순 업체 목록 1~20건 확인 가능.
- **SEARCH-AC45:** 로딩 중이거나 오류가 났을 때 첫 페이지 20건/불명확한 건수를 `전체 업체 N곳`으로 잘못 표기하지 않는다.
- **Q15 확정:** 펼친 목록에서 행 탭 시 지도 카메라를 해당 업체로 이동하고 선택 카드로 접는다. 상세 이동은 별도 상세 버튼.

## 16. Q15~Q24 일괄 확정 기능 수용 기준 (2026-11-04)

- **SEARCH-AC47 (Q16):** 펼친 목록은 약 85% 화면 높이로 확장하지만 기기 하단 탭/안전 영역을 가리지 않는다. 손잡이와 닫기/접기 동작 제공.
- **SEARCH-AC48 (Q17):** 검색창 타이핑만으로 검색 요청이 발생하지 않는다. 키보드 검색/제출에서 검색이 시작되고 기존 적용 영역에서 요청·목록 초기화를 수행한다.
- **SEARCH-AC49 (Q18):** 업체 유형·품목·배송 가능 필터를 선택할 수 있다. 동일 검색 결과 집합에 필터가 반영되고, 미지원 API 필드를 백엔드로 무검증 전송하지 않는다. 기존 API는 `category`는 있지만 품목/배송 독립 필터는 미지원이므로 계약 확장 필요.
- **SEARCH-AC50 (Q19):** 기본 정렬은 거리순 유지. 품목 검색 중에만 가격순 정렬 전환 선택지가 나타난다. 단, 여러 가격/규격을 가진 업체의 비교 가격 산식은 미확정이므로 새 구현 계약 승인 전 실제 가격순을 임의 개발하지 않는다.
- **SEARCH-AC51 (Q20):** 위치 허용 시 단말 현재 위치, 미허용/오류 시 아주대 부근 기본 중심으로 시작하고 안내 문구를 구분한다.
- **SEARCH-AC52 (Q21):** 0건 빈 상태는 '검색 결과 없음'과 검색 조건 초기화 액션을 제공; 네트워크/서버 오류는 별도로 표시.
- **SEARCH-AC53 (Q22):** 가격·배송 조건이 미확인일 때 `가격 문의` / `배송 정보 없음`을 사용한다. 무료 또는 0원을 추측해서 표시하지 않는다.
- **SEARCH-AC54 (Q23):** 업체 하단 카드에는 `저장` 토글과 `업체 상세 보기` CTA가 모두 있고, 저장 상태가 시연 세션에 반영된다.
- **SEARCH-AC55 (Q24):** 대량 검색 시 서버 페이징·분할·집계로 전체 영역 일치 업체를 검색/클러스터 대상에 포함한다. 일부만 조회했는데 전체인 것처럼 수치를 표시하지 않는다. 과도한 광역 검색의 별도 성능 계약은 미결정.

### 필터 및 정렬 구현 경계
기존 Zod·DB에 없는 필터나 정렬을 문서상 승인된 UI 요구만으로 이미 제공되는 기능이라 간주하지 않는다. 새 계약을 확정할 때 검색 조건 키, 결과 집합 일관성, DB/RLS, 페이지 순서와 클러스터 숫자에 동일하게 적용한다. 다중 매치 품목의 가격순 정렬 산식은 임의 최저가를 선택하지 않고 후속 설계에 명확히 제시한다.
