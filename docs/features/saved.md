# FEATURE-SAVED-001 — 저장 (업체 + 커뮤니티 게시글)

**상태:** S-01~S-10 사용자 승인(2026-11-04). 실제 구현은 아직 시작하지 않았으며 API 경로/스키마/테이블 이름은 개발 제안이다.

## 목적·진입
- 앱 하단 다섯 개 탭 `지도 | AI 도우미 | 커뮤니티 | 저장 | 내 정보` 중 `저장`.
- 로그인 화면 없이 안전하게 만들어진 **시연 세션**의 본인 저장 항목만 조회·수정.
- 업체 상세·지도 선택 카드에서 업체 저장, 커뮤니티 피드/상세에서 게시글 저장. 각 저장 아이콘은 현재 상태를 보여준다.

## 확정 수용기준(S-01~S-10)
| ID | 정책 | 수용 조건 |
|---|---|---|
| S-01 | 저장 대상은 업체와 커뮤니티 게시글 | 하나의 저장 탭에서 두 종류 접근 |
| S-02 | 북마크를 누르면 즉시 저장/해제 | 중복 저장 없음; 요청 실패 시 UI 롤백·재시도 안내 |
| S-03 | `전체 / 업체 / 게시글` 세그먼트 | 각 탭의 목록이 동일 저장 상태와 동기화됨 |
| S-04 | 업체 카드는 업체명·유형·주소·최근 확인일 | 미확인 날짜는 `정보 확인일 없음`, 임의 생성 금지 |
| S-05 | 게시글 카드는 제목·분류·작성자·작성일 | 시연 닉네임과 서버 작성일 표시 |
| S-06 | 최근 저장한 순 기본 | `saved_at DESC, stable_id DESC`로 안정적인 페이지 순서 |
| S-07 | 업체/게시글 선택 시 각각 상세 이동 | 이전 지도 검색 위치 유지; 삭제된 항목은 상세로 이동 불가 |
| S-08 | 북마크 재선택 즉시 해제 | 동일 ID에 여러 번 요청해도 중복 레코드 발생 금지 |
| S-09 | 삭제/비공개 자료 보호 | 미접근 항목에는 이름/가격/본문/이미지 등 민감한 상세 노출 금지; 접근 불가 표시 또는 안전하게 목록 제외 |
| S-10 | 세션 동안 유지, 새 시연 시작 시 자동 초기화 | 다른 시연/실제 운영 데이터 영향 없음 |

## 사용자 흐름
1. 지도에서 업체 핀 선택 → 하단 업체 카드의 북마크 선택 → 저장 상태 즉시 반영.
2. 커뮤니티에서 게시글 저장 → 같은 시연 세션의 `저장` 탭 `전체`, `게시글`에 나타남.
3. `저장` 탭의 필터와 목록은 세션의 서버 저장 상태를 단일 소스로 조회한다. 탭 이동 후에도 유지.
4. 항목 선택 → 각 상세 페이지로 이동. 업체 상세, 지도 카드, 게시글 상세의 북마크 상태는 일치한다.
5. `새 시연 시작` → 이전 세션 저장 데이터 접근 차단 및 자동 초기화.

## 제외 범위·예외
- 로그인/회원가입, 공유 북마크/폴더, 외부 알림, 주문/결제는 시연 범위 제외.
- 권한이 없는 데이터가 저장 API에 전달되면 404로 감춰서 존재 여부 유출 방지.
- 업체 공식 데이터 조회는 원본 읽기 전용. 저장 상태만 demo store에 기록.
- 커뮤니티 게시글은 `community_post_saves`와 **동일 레코드 사용**, 별도의 두 번째 '게시글 저장' 테이블을 만들지 않음.
- 기존 공동 커뮤니티 API `PUT/DELETE /api/v1/community/posts/{postId}/save`를 재사용. 저장 탭 조회 결과에 같은 상태를 투영.

## 의존 API·DB·UI
- 신규 제안 `GET /api/v1/saved` (두 종류 통합 조회).
- 신규 제안 `PUT/DELETE /api/v1/saved/vendors/{vendorId}`.
- 기존 커뮤니티 설계 API `PUT/DELETE /api/v1/community/posts/{postId}/save` (미구현).
- `docs/database/saved.md`, `docs/ui/screens/saved.md`, `docs/api/saved/`.
- 현재 `main`의 모바일 탭은 4개이며 저장 탭이 없다. 실제 수용 테스트 전까지 완성으로 표시 금지.
