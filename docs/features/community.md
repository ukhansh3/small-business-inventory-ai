# FEAT-COMMUNITY-001 — 사장님 커뮤니티 (시연 P1)

**결정 상태:** 2026-11-04 C-01~C-10 사용자 일괄 승인. **구현 상태:** `main`에는 정적 예시 글만 있으며 읽기/쓰기/댓글 API 및 신규 DB는 미구현.

## 목적 및 범위

로그인 화면이 없는 데모에서 사장님들이 구매처 질문, 가격 제보, 거래 경험에 관한 글을 작성하고 다른 시연 글을 읽고 반응한다. 저장·좋아요·댓글·신고가 실제 시연 데이터에 기록된다. 채팅/실거래/결제, 대댓글 및 실사용자 공개 게시판은 시연 범위 밖이다.

| ID | 승인된 기능 | 수용 조건 |
|---|---|---|
| C-01 | `전체`/`구매처 질문`/`가격 제보`/`거래 경험` | 전체는 목록 필터, 글 작성시 나머지 3개 중 필수 선택 |
| C-02 | 피드는 최신순+카테고리 | 정렬 `created_at DESC, id DESC`, 페이지 추가 시 중복/역순 없음 |
| C-03 | 제목·본문·카테고리·사진 작성 | 서버 검증·첨부 권한 검증·작성 완료 목록 반영 |
| C-04 | 댓글 작성/조회/삭제, 대댓글 없음 | 게시글별 평면 댓글, 자신이 작성한 댓글만 삭제 |
| C-05 | 좋아요·게시글 저장 | 반복 탭/동시 요청 시 중복 반응 카운트 없음 |
| C-06 | 게시글 상세 | 본문, 출처/작성자 닉네임, 사진, 댓글 및 작성 일시 표시 |
| C-07 | 본인 글·댓글 수정 및 삭제 | 서버에서 `demo_session_id + author_id` 검증. 타인 글 직접 변경 불가 |
| C-08 | 자동 시연 닉네임 | 화면 진입 시 자동 부여, 로그인 UI 없음, 계정 개인 정보 요구 없음 |
| C-09 | 신고/시연 관리자 숨김·삭제 | 신고자와 별도의 시연 관리 능력; 격리된 세션 내에서만 관리 가능 |
| C-10 | 시연 데이터 분리·리셋 | 새 시연 시작 시 글/댓글/사진/반응/신고/관리상태 초기화. 업체 가격 마스터 자동 변경 절대 금지 |

## 사용자 시나리오
1. 앱에서 `커뮤니티` 탭 진입 시 로그인 화면 없이 최신 글 피드 표시. `전체`가 기본 필터이다.
2. `가격 제보` 탭 선택 → 같은 시연 세션에 속한 해당 카테고리 글만 새로 표시한다.
3. 우측 하단 주황 글쓰기 버튼 → 카테고리, 제목, 본문, 선택적 사진 작성 → `등록` → 상세나 목록에 새 글 반영.
4. 글 상세에서는 전체 본문/이미지/작성 시각/닉네임/댓글과 좋아요, 저장, 신고를 볼 수 있다.
5. 시연 닉네임이 같은 세션의 **작성자 식별자와 일치**할 경우만 글/댓글 수정·삭제 버튼 활성화. 비활성화가 아닌 백엔드 권한 검증 필수.
6. 신고 접수 → 시연 관리 화면에서 해당 세션의 접수 글을 확인하고 숨김/삭제 조치. 숨김 이후 목록/상세/API에서 비관리자에게 표시하지 않는다.
7. 새 시연 시작 → 해당 시연의 작성 글·이미지·댓글·좋아요·저장·신고·관리 상태 리셋. 실제 업체/운영 자료와 타 시연은 불변.

## 데이터·정책 경계
- 커뮤니티 가격 제보는 **사용자 주장**이지 인증된 `vendor_items` 가격 정보가 아니다. 별도 게시글 텍스트·첨부로 저장하고 공식 가격 API/AI 가격 카드에 자동 반영하지 않는다.
- 공개 승인 실제 업체 내용은 읽기 전용이며, **커뮤니티 쓰기 자료는 데모 세션 범위**에만 존재한다. 비공개 운영 정보나 다른 시연 세션 데이터를 피드에 혼합하지 않는다.
- `전체`는 글 카테고리 저장값으로 사용하지 않는다. 카테고리 값은 백엔드 enum으로 검증.
- 글/댓글 작성자 닉네임은 화면 표현값이고 **권한 판단은 세션에 묶인 불변 작성자 ID**로 한다. 닉네임 변경·중복으로 소유권이 바뀌지 않는다.
- 사진은 허용 MIME·크기·장수와 스토리지 경로 격리 검증 후 업로드. 개인 정보나 불필요한 위치 데이터는 저장하지 않으며 EXIF 제거를 우선한다.
- 삭제는 데모 UI에서는 삭제됨으로 표시하되, 저장/미디어 정책과 신고 증거 유지 범위를 기술 결정 전까지 임의 확정하지 않는다. `visibility` (published/hidden/deleted) 분리는 요구.

## 승인 범위와 아직 미정인 기술 상세
- 실제 API path/method, UUID/ULID, cursor 형식, 기본 게시글 이미지/댓글 수 제한, 글자수 제한, 저장/좋아요 호출 규격, 시연 관리 접근 경로 및 구현, 자동 초기화 트리거/TTL은 **기술 제안**이다.
- 안전한 기본 구현안을 문서에 제시하지만, 에이전트가 그것을 이미 사용자 승인된 계약으로 오인해서는 안 된다.
- 시연 관리자가 실제 스태프 권한을 획득하거나 실제 공개 업체를 숨기지 못하도록 서버/DB 레벨 분리.

## 수용 테스트
- C-AC01: 카테고리 필터 `전체`와 세 카테고리 표시/조회 일치.
- C-AC02: 최신순 페이징 중 동일 글 중복/누락 및 날짜 오름차순 회귀 없음.
- C-AC03: 유효한 제목/본문/카테고리/사진 등록 시 상세/목록 동기화; 유효하지 않은 데이터 서버 거절.
- C-AC04: 댓글 추가/수정/삭제, 대댓글 생성 요청 거절.
- C-AC05: 좋아요/저장 토글 중복 호출 시 두 번 카운트 되지 않음.
- C-AC06: 상세의 글 내용/이미지/작성자/댓글 표시.
- C-AC07: 작성자 A는 A의 글/댓글만 수정·삭제, 작성자 B의 리소스 조작은 403/404로 거절.
- C-AC08: 첫 진입 시 닉네임 자동 부여, 비로그인 사용 흐름 유지, 임의 닉네임으로 권한 상승 불가.
- C-AC09: 신고 접수·관리자 검토·숨김/삭제. 일반 사용자는 관리 API 거부. 시연 관리만 수행 가능.
- C-AC10: 새 시연 시작 시 세션 A 데이터만 리셋, 타 세션·공식 업체 가격/마스터 데이터 불변.
- C-AC11: 저장소 사진과 RLS를 포함하여 세션 경계 누출 없음; 삭제/리셋 후 이전 이미지 URL 무효 또는 접근 차단.
- C-AC12: 관리자 숨김·삭제된 글이 목록/상세/검색/저장 목록/AI 사실 입력으로 재노출되지 않음.
