# FEATURE-PROFILE-UI — 내 정보·업체 관리 UI 전용 (실제 구현 연기)

**상태:** 사용자 확정(2026-11-04). **이번 데모에서는 UI만 구현.** 업체 등록·수정·승인 워크플로의 신규 백엔드/API/DB 작업은 후순위. 기존 구현 코드는 삭제하지 않고 보존.

## 데모 P0 UI 범위
- 하단 탭 명칭: `내 정보` (현재 main의 `내 업체`에서 명칭 변경 예정).
- 상단 `내 정보`, 시연용 자동 닉네임/시연 모드 안내.
- `내 업체 관리` 섹션: 등록 업체 목록 상태 카드(예시), `업체 등록`, `업체 수정`, `검토 상태`, `승인 내역` 등 향후 기능의 탐색 구조.
- 정보가 실제 저장/심사/승인된 것처럼 보이지 않도록 **`시연 화면 · 업체 관리 기능 준비 중`** 구분. 클릭 불가 버튼은 `준비 중`으로 명시하거나 안내 메시지 표시.
- 로그인/로그아웃 화면은 노출하지 않는다. 시연 세션은 하단 기능들(커뮤니티/저장/AI)을 위한 내부 인증이며 사용자에게 로그인 강요 금지.

## 이번 데모 제외
- 업체 등록/수정 제출, 이미지 업로드, 승인/반려, 운영자 권한/검토 대기열, 기업 실계정 관리.
- 위 기능에 대한 새로운 API, DB migration, 승인 RLS 구현 및 종단 간 업무 흐름 테스트는 진행하지 않음.
- 예외: 다른 기능을 위해 필요한 공통 시연 세션/저장·AI·커뮤니티 API는 범위 유지.

## 기존 코드 보존
- `apps/mobile/src/app/(tabs)/profile.tsx`: 현재 로그인/업체 워크스페이스에 연결되므로 UI 전용 화면으로 안전하게 교체하거나 별도 데모 화면 레이어 사용. 라우트/API 호출은 숨김, 기존 `register`, `moderation` 등 구현 파일은 제거하지 않음.
- 실제 업체 등록/승인 API와 DB가 이미 일부 존재한다는 이유로 새로운 시연 기능처럼 표시하지 않는다.
- 신규 P0 통합 작업에서 운영 데이터에 가짜 승인 레코드 쓰기 금지.

## 추후 P1+ 단계
- 서비스 운영 정책, 업체 대표 본인인증, 승인 워크플로, OAuth 도입을 별도 설계/승인 후 작업. 이때 기존 `main` 구현 상태를 재검토하여 재사용/리팩터링 여부 결정.
