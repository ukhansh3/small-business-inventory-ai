## 이번 변경

1. SPEC에 현재 MVP 포함/제외와 AC·구현·검증 연결을 명시했다. 회원 기능은 새 기능을 발명한 것이 아니라 현재 코드와 승인 정책에 기준을 붙였다.
2. 앱 README에 main 기준 실행 방법과 핵심 사용 순서·기대 결과·AC를 연결했다. 루트 README의 로컬 수정안은 후속 요청에 따라 반영에서 제외했다. 현재 코드의 수량 누락 허용, 위치 변경, 3MiB 이미지 상한과 stateless 세션을 문서에 맞췄다.
3. 커뮤니티 정상 등록·제목/댓글 경계·신고 자동 숨김 금지·북마크 소유권·대화 참가자·리뷰 별점·저장소 장애 테스트를 10개 추가했다.
4. 기존 린트 오류를 고쳤다. 위치 초기 요청은 성공 시 오류를 해제하고, 지도 콜백/AI 상태 ref는 렌더 외부에서 동기화하며, 재시도 함수는 이름 있는 함수로 유지했다. 사진 채점기의 쉼표식을 같은 동작의 블록으로 정리했다.
5. 오래된 E2E를 현재 하단 탭·수량 생략 흐름에 맞췄고, 브라우저 경로를 환경 변수로 지정할 수 있게 했다. CLI 실행 성공과 수동 브라우저 확인은 구분한다.
6. CI 정의에 린트·결함 주입·웹 빌드를 추가했다. 이 브랜치의 GitHub CI는 아직 실행되지 않았다.

환경은 Windows, Node.js 24.14.0, npm, 앱 lockfile의 의존성이다. 운영 DB·실시간 AI 키를 넣지 않은 stored 모드로 확인했다. 지도에는 기존 공개 JavaScript 키를 사용했고 키 값은 기록하지 않는다.

### Evals 기준선 재확인

이번 작업에서는 유료 실시간 모델을 다시 호출하지 않았다. 기존 결과를 채점 코드로 재확인했다.

- JSONL 원문의 SHA-256과 현재 `loadDataset().items`의 해시가 저장된 결과와 일치했다.
- 32개 기대값과 저장된 행의 기대값이 일치하고, 현재 채점기의 오답 필드·조건 정확도와 저장 점수가 일치했다.
- 전체 31/32, 조건 일치 21/22(95.45%)를 확인했다. `p06`은 실패로 보존한다.
- 로컬에 보존된 실행 기준 커밋 `f63f997`과 분기 기준 main의 텍스트 AI 코드·프롬프트·스키마·품목 카탈로그 차이가 없었다.
- 당시 결과가 최신 배포 서버의 모델 설정·지연·가용성을 다시 측정했다는 뜻은 아니다.

## 로컬 브라우저 확인

`npm run dev:api`와 `npm run web`을 띄우고 앱 내 브라우저에서 `http://localhost:8081/?test=1`을 확인했다. 모바일 미리보기는 390×844다. Supabase 계정 없이 가능한 흐름을 실제 로컬 API에 연결해 확인했고 모델 해석은 stored 모드다.

| 확인한 행동 | 관찰 결과 |
|---|---|
| 지도 첫 화면 | 카카오 지도·업체 핀·목록 열기 표시 |
| AI 도우미에 상추 입력 | 수량 질문 없이 시점 → 수령 방법 질문 |
| 지금 바로·직접 갈게요 선택 | 양 미정 상태로 후보 9곳 표시 |
| 검색 결과 지도에서 보기 | 지도와 결과 목록으로 연결 |
| 상추 2키로 만원 부르던데 | kg당 5,000원, 예시 포함 시세 표시 |

CLI `npm run e2e`는 Chrome 미발견, 명시적 Edge 경로에서는 프로세스 시작 오류로 브라우저 실행 전에 실패했다. 이 환경 제약을 테스트 통과로 계산하지 않는다. 준비한 E2E 3건의 CLI 통과 기록은 없다. 앱 내 브라우저 관찰과 자동 E2E 결과를 바꿔 적지 않는다.

## 남은 실연결 확인

- 실제 테스트 계정의 인증 메일·로그인·커뮤니티 작성·저장·다른 사용자 권한·리뷰·문의 왕복은 이번에 운영 DB를 사용하지 않아 미확인이다. 본인 테스트 계정과 `[가상테스트]` 글을 사용해 확인하고 결과를 추가한다.
- 실시간 텍스트/사진 AI의 현재 배포 가용성은 별도다. 필요 시 실제 모델·프롬프트·카탈로그 조건을 기록해 새 결과를 추가하며 기존 결과는 보존한다.
- 이 변경의 main 반영은 사용자 승인 범위다. 실제 반영 결과는 PR에서 확인한다. 배포는 민혁 관리이며 main 병합과 Vercel 반영을 동일시하지 않는다.
- 이 문서의 미확인을 없애기 위해 범위를 사후 축소하거나 합격선·기대값을 바꾸지 않는다.
