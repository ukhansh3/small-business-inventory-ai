# ADR-008: 민균 브랜치에서 업체 등록 DB 규칙 구현

- 날짜: 2026-10-28
- 상태: 사용자가 작성된 DB 규칙대로 민균 브랜치에서 구현하도록 명시 요청. 코드·SQL 구현 승인 범위이며 공유 DB 적용과 운영자 계정 지정은 별도다.

## 결정

업체 직접 등록, 업체별 품목·필수 가격, 운영자 확인 후 공개를 SQL/RLS/RPC와 사용자 토큰 기반 API 및 모바일 등록·검토 화면으로 구현한다. 승인본과 수정본을 분리하고, 초안 저장·요청 취소·새 수정본·승인·보완·숨김·철회·사진 비공개를 지원한다. 단가 검색·커뮤니티·AI 등 기존 미승인 계약 전체를 함께 확정하지 않는다.

비로그인 공개 여부는 미결정이므로 로그인 사용자만 승인 공개본을 조회하도록 보수적으로 제한한다. 운영자 권한은 신뢰할 DB 관리자가 지정하며 앱에서 선택하지 못한다. 계정 생성이 업체 실재 인증을 뜻하지 않는다. 신규 Supabase JS와 Expo SecureStore/Crypto는 기존 결정 스택과 모바일 세션·요청 식별에 사용한다. PGlite/PostGIS는 공유 DB를 변경하지 않는 테스트 전용 의존성이다.

## 계약과 증거

- docs/contracts/vendor-registration-v1.md와 packages/vendor-contracts/index.ts가 이번 구현의 범위·요청·응답 정본이다.
- supabase/migrations/202610280001_vendor_registration.sql에 실제 적용 SQL을 둔다.
- 기존 SPEC/ontology 상단에서 이번 보충 계약을 연결한다. 다른 제품 가설이나 인터뷰 증거를 검증 완료로 바꾸지 않는다.
- 공유 Supabase 조회·수정·리셋·운영자 계정 생성은 자동 수행하지 않는다. 실제 적용 전 기존 스키마와 권한을 확인해야 한다.

## 2026-10-29 실제 DB 적용

사용자가 실제 Supabase 적용을 명시 요청했다. 기존 테이블 충돌과 Storage RLS를 점검하고 SQL Editor에서 migration 전체를 실행했다. 9개 테이블·13개 RPC·PostGIS·비공개 사진 버킷 및 역할별 권한 확인을 완료했다. 상세 증거는 docs/database/deployments/2026-10-29/README.md에 둔다. 사용자 데이터 생성·운영자 지정·Git main 병합·서버 배포는 수행하지 않았다.
