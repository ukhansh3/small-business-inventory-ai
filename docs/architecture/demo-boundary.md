# 공통 시연 세션 — 권한/격리/초기화 설계 (기술 제안)

## 사용자에게 보이는 동작
- 앱 실행 시 로그인 페이지 없음. 내부 세션을 발급하거나 기존 유효 세션을 복구한다.
- 데이터는 시연 중 유지. **명시적 `새 시연 시작`** 시 지금 세션의 댓글·게시글·저장·AI 기록 등이 초기화됨.
- 새 시연 시작과 단순 앱 재실행은 구별한다. 단순 화면 이동·프로세스 재시작을 이유로 임의 삭제하지 않는다.
- 원래 공개 업체 정보는 시연 초기화 대상이 아님.

## 후보 인증 방식
- 서버/DB 세션 소유권에 연결되는 Supabase anonymous Auth(익명 계정) 또는 이에 준하는 비대화형 토큰. `auth.uid()`와 `is_anonymous`를 함께 확인해야 함. 익명 계정 기능이 실제 프로젝트에 켜져 있는지 별도 검증 필요.
- JWT·토큰이 없는 요청은 **무조건 성공시키지 않고** 내부 세션 복구/자동 재발급 흐름을 사용. 실패하면 오류 UI, 임의 공용 계정 공유 금지.
- 시연 role은 서버에서 검증; 클라이언트 `isModerator:true`는 권한 근거 아님.

## 권장 초기화 시맨틱
1. 시연 생성: 서버 인증 주체와 session_id를 바인딩, demo_actor 닉네임 자동 생성(PII 금지).
2. 모든 쓰기/조회: `session_id=server-authenticated session` 강제, 타 세션 참조는 `404`(존재 여부 숨김) 또는 엄격한 403.
3. 명시적 새 시연 시작: 이전 세션에 속한 AI messages, thread, vendor saves, community posts/comments/likes/saves/reports/images 업로드를 **테이블 종속성 역순** 정리/격리하고 새 session_id 발급. 시연 세션 간 상호 영향 0건.
4. GC/TTL: 서버 스케줄 별도, 만료 재시도 안전성; 프로덕션 승인 업체/원본 이미지 삭제 0건 보장.
5. 대화/게시글/image 업로드에는 server-issued IDs, idempotency key, session RLS.

## 차단 조건
- 운영/시연 DB를 분리하지 않는데 `anon`/`authenticated`가 실제 업체 등록/심사 API를 실행할 수 있으면 릴리스 중단.
- 사용자 아이디/별명/역할/세션 ID를 요청 body만으로 신뢰하거나 하드코딩 공용 actor를 사용하면 중단.
- DB reset 범위/순서와 Storage 객체 삭제가 검증되지 않으면 시연 리셋 기능 완료 선언 금지.

## 기술적으로 아직 미확정
- 물리적으로 별도 프로젝트인지, 세션 TTL 값/GC 주기, 모델/지도 서비스 키 제공처, 시연 관리자 역할 부여 및 UI 입구. 작업 시작 전 단일 승인 묶음으로 확인할 것.
