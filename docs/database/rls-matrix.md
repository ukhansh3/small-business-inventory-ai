# DB RLS/접근 제어 매트릭스 — 필수 테스트 목표

| 자원 | 익명 시연 참여자 | 시연 작성자 | 시연 moderator | 운영 staff / 기존 사용자 | 타 세션 |
|---|---|---|---|---|---|
| 공개된 실제 업체/품목 | 읽기만 | 읽기만 | 읽기만 | 기존 운영 규칙 | 공개 조회 범위만 |
| 실제 업체 draft/revision/검토 | **금지** | **금지** | **금지** | 기존 운영 규칙 | 금지 |
| 시연 sessions/actors | 자기 유효 세션 | 자기 세션 | 맡은 시연 세션 | 승인 없이는 열람 금지 | 금지 |
| 시연 AI 대화 | 자기 세션 R/W | 자기 세션 R/W | 관리자 검토는 별도 승인 필요 | 기본 금지 | 금지 |
| 커뮤니티 글 | 같은 세션 공개글 R | 작성자만 W/수정/삭제 | 시연 범위 hide/delete | 기본 금지 | 금지 |
| 댓글 | 같은 세션 공개댓글 R | 작성자만 W/수정/삭제 | 신고 처리 범위만 | 기본 금지 | 금지 |
| 좋아요/게시글 저장 | 내 actor 토글 | 내 actor 토글 | 타인 저장 무단 변경 금지 | 기본 금지 | 금지 |
| 업체 저장 | 내 actor 토글 | 내 actor 토글 | 타인 저장 무단 변경 금지 | 기본 금지 | 금지 |
| 사진 Storage | 공개 가능한 세션 글의 안전한 읽기 | 자기 글/업로드 제한 쓰기 | 허용된 시연 글 moderation | 기본 금지 | **다른 세션 비공개** |
| Reset | 자기 세션 종료/새 세션 시작 | 자기 세션만 | 다른 세션 reset 금지 | 별도 소유자 승인 | 금지 |

**유의:** Supabase `authenticated` 역할만 확인하면 익명 계정도 같은 롤을 가질 수 있다. 서명된 사용자 신원, anonymous claim, 세션 소유 및 공개 정책을 별도 검증해야 한다. DB RLS alone가 어려운 Storage 업로드에는 서버 소유권 체크를 추가.

필수 음성 테스트: A세션 글을 B세션에서 ID 직접 접근, 가짜 actor/moderator body 위조, 탈퇴/초기화된 세션 stale token, 다른 세션 Storage URL, 익명 계정으로 실제 업체 등록/검토, bulk reset의 실업체 불변.
