# UI 명세 에이전트 지침 — 제안안

이 폴더에서 작업할 때 **최신 `docs/decisions/approved-ux.md`**와 루트 `AGENTS.md`, 채택된 ADR, `SPEC.md`, 기능 명세, 공용 API Zod 계약을 함께 읽는다.

1. **승인된 화면 구조와 미승인 디테일을 구분한다.** `지도 중심 + 핀→하단 카드 + 위로 펼쳐 목록`은 승인되었다. 핀 레이블의 **검색 전 업체명만 / 단일 검색 일치 품목·가격 표시**는 승인되었다. 다중 일치 품목은 `일치 품목 N개`로 승인되었다. 지도 이동/확대/축소 후에는 `이 지역 검색` 버튼을 표시하고 눌렀을 때만 재검색한다. **초기 시트 상태는 접힌 결과 요약바(Q14 A)로 승인되었고, 정확한 시트 높이·광역 검색 상한·전체 결과 확보 기술 방식은 미정**, 목록 기본 정렬은 마지막 적용된 가시 지도 중심점에서 거리순(Q12 A)으로 확정이다. **Q11 A에 따라 지도는 전체 일치 업체, 목록은 20건씩 추가 로딩**한다.
2. 사용자가 제공한 목업을 해당 기능의 레퍼런스로 유지한다. 목업 텍스트는 검정 계열이며 주황색을 주요 강조로 사용한다. 색상 HEX는 디자인 시스템에서 승인한 값을 따른다.
3. 화면별 문서에는 화면 ID/목적, 와이어프레임, 레이아웃, 각 컴포넌트, 사용자 이벤트, API 필드 매핑, empty/loading/error, 모바일 대응, 접근성, 수용 기준을 적는다.
4. 목업에 있다고 실제 API/DB에서 지원되는 것으로 가정하지 않는다. 예: 배송 필터, 핀 가격의 **복수 품목 선정**, AI 실검색.
5. API 요청·응답 필드를 UI 명세에서 새로 만들어내지 않는다. `packages/vendor-contracts` 및 `docs/api/`를 참조하고 차이를 `contract gap`으로 기록한다.
6. 사용자 질문이 필요한 사항은 `미결정`으로 명시하고 임의로 확정하거나 구현 지시하지 않는다.
7. 지도 WebView 메시지는 반드시 신뢰 origin과 허용된 업체 ID로 검증한다.
8. UI 구현 완료는 Android/iOS 양쪽 실제 테스트를 수행한 범위까지로만 표기한다. 코드 존재만으로 검증 완료를 주장하지 않는다.
9. 사용자 승인 없이 실제 운영 DB, 권한, 비밀키, 다른 팀원 브랜치 코드를 변경하지 않는다.
10. 문서 변경 시 관련 기능·API·DB·수용 기준 참조가 깨졌는지 검토한다.

11. `Q-SEARCH-07(A)` 승인: `이 지역 검색`은 지도에 현재 보이는 bounds를 기준으로 동작한다. 원형 고정 3km 조회와 동일하다고 가정하지 않는다. 기존 API·DB에는 bounds 검색이 없어 **별도 계약 변경과 검증**이 필요하다. 변경 전까지 제안 필드를 확정 계약으로 소개하지 않는다.

12. **Q-SEARCH-10(A) 승인:** 지도 밀집 업체는 업체 수를 표시하는 클러스터로 묶고 확대 시 개별 핀으로 분리한다. 품목 수와 업체 수를 혼동하지 않는다. 클러스터링 재배치를 `이 지역 검색`의 자동 API 호출로 연결하지 않는다. 클러스터 **탭 동작은 Q13 A로 확정(군집으로 확대 후 `이 지역 검색` 버튼 노출, 자동 API 호출 없음)**. 전체 지도 조회의 기술 방식·상한은 미정이므로 임의 구현 계약으로 고정하지 않는다. **목록 첫 20건만으로 지도 클러스터 전체 업체 수를 표시하지 않는다.**

13. **Q13 A 승인:** 숫자 클러스터 탭은 지도 확대 이벤트이며 업체 선택 이벤트가 아니다. 해당 클러스터 영역으로 카메라 이동·확대 후 클러스터를 재계산한다. `이 지역 검색`을 표시하고 사용자가 누르기 전에는 검색 API를 호출하지 않는다. 정확한 확대 레벨·클러스터 반경은 미정이므로 임의로 출시 계약에 박지 않는다.

14. **Q14 A 승인:** 첫 실행 시 하단 시트는 접힌 결과 요약바로 시작하고, 개별 업체 핀을 탭하면 선택 업체 카드로 전환한다. 확대된 업체 미리보기 목록을 초기 상태로 만들지 않는다. 요약바의 전체 업체 수는 Q11 전체 조회 결과 기준이며 불완전한 첫 20건을 전체로 표시하지 않는다. Q15 확정: 펼친 목록 행 탭 → 지도 카메라 해당 업체로 이동 → 선택 업체 카드로 접는다. 상세는 별도 버튼.

15. **AI-01~AI-10 확정:** `docs/features/ai-assistant.md` 및 `docs/ui/screens/ai-assistant.md`의 채팅·추천 카드·지도 연동·세션 보존 요구를 준수한다. 현재 모바일 AI 탭은 샘플 키워드 검색일 뿐 실제 모델 연결이 아니다. 모델 키를 UI에 넣지 않고 서버의 검증된 추천 결과 필드만 카드에 표시한다. 같은 단위 비교가 불가능한 가격으로 '최저가' 문구를 만들지 않는다. 실제/가상 출처를 구분하며 임의 가격·업체를 생성하지 않는다.

## 커뮤니티 추가 UI 구현 규칙 (2026-11-04, C-01~10 확정)
- `docs/ui/screens/community.md`, `community-post-detail.md`, `community-compose.md`, `community-moderation.md`를 읽고 구현할 것. 정적 2건을 실제 DB와 연결된 게시판이라고 주장하지 말 것.
- 카드·칩·주황 글쓰기 FAB·검정 본문 텍스트는 사용자 제공 목업을 우선한다. 임의로 남색 기본 텍스트를 디자인 확정으로 삼지 말 것.
- 로그인 UI 없이 작성 가능해야 하지만 시연 세션·actor 인증과 RLS/Storage 권한 검증이 준비되지 않았으면 서버를 열린 쓰기로 변경하지 말 것.
- 가격 제보를 `vendor_items` 공식 가격으로 쓰거나 AI가 확정 가격으로 인용하도록 연결하지 말 것.
- 커뮤니티 API 문서의 경로/숫자 상한은 기술 제안이므로 실제 구현 전 contracts, migrations, 권한, 테스트 범위를 함께 검토할 것.

## 저장·내 정보 UI 범위 정책 (2026-11-04 최신)
- 저장 탭 S-01~S-10: `docs/ui/screens/saved.md` 구현, 업체·게시글 저장 상태가 서로 다른 화면에서 동기화돼야 한다. 각 상세 조회 가능 여부 확인 후 노출; 타 세션/삭제·숨김의 텍스트 노출 금지.
- 5탭 구성을 `지도/AI 도우미/커뮤니티/저장/내 정보`로 맞춘다.
- **내 정보는 UI 전용**: `docs/ui/screens/profile-ui-only.md` 확인. 이번 데모에 새 업체 등록/수정/심사 API·DB 작업을 배정하지 않는다. 기존 코드는 삭제하지 않는다. 미구현 상호작용은 `준비 중` 표시.
- 데모 AI/커뮤니티/저장과 달리 업체 관리 화면은 기능 완성을 요구하지 않는다. 기존 AGENTS.md 내 Q15 미결정 같은 과거 정보는 `DECISIONS.md` 최신 일괄 승인에 의해 대체된다.

## 최종 공통 원칙 (v3.0 정리)
- 이전 절의 미결정 표시는 `docs/decisions/approved-ux.md`의 최신 승인에 의해 대체된다.
- 검정 본문, 주황 액센트, 5개 탭, 지도 중심 하단 시트 구성은 확정. 정확한 HEX/컴포넌트 크기는 디자인 **제안**이며 픽셀 확정이 아님.
