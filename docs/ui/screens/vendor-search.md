# UI-SEARCH-001 — 지도 탐색 홈 (화면 상세 명세)

- **결정 상태:** 레이아웃 **A 승인**, 핀 레이블 **A 승인**(검색 전 업체명 / 단일 품목 시 품목·가격 / 다중 일치 시 개수만); 세부 동작·디자인 토큰 초안
- 디자인 기준: 사용자가 제공한 `지도 탐색 / AI 도우미 / 사장님 커뮤니티` 목업 중 첫 번째 지도 화면
- 참고 색상: 주황 강조, **검정 계열 텍스트**, 흰 배경, 연회색 카드. 목업에서 정확한 HEX 확정 전까지 색상은 후보로 표기한다.
- 현재 실행 소스: `apps/mobile/src/app/(tabs)/index.tsx`, `src/components/KakaoMap.tsx`, `apps/cheonhajangsa/app/mobile-map/page.tsx`

## 1. 핵심 승인사항
- **지도 중심 전체 화면**: 지도는 정해진 높이(현재 330px) 컴포넌트가 아니라 본문 대부분을 차지하는 기본 캔버스.
- **핀 선택 = 하단 업체 카드**: 탭 시 상세 화면으로 즉시 이동하지 않음.
- **하단 카드 위로 스와이프 = 현재 검색결과 업체 목록**.
- **Q14 A 승인: 첫 진입 시 하단 시트는 접힌 결과 요약바. 개별 업체 핀 탭 시 선택 업체 카드로 전환**. 초기부터 업체 1~2개 미리보기를 보여주지 않음.
- **하단 시트를 내려 접으면 지도 영역을 다시 넓게 봄**
- **검색 전 핀은 업체명만 표시**, **단일 품목 일치에는 해당 품목·가격**, **2개 이상 품목 일치에는 `일치 품목 N개`만 표시**한다. 다중 일치 항목의 개별 가격은 선택 카드에서 표시한다.
- **지도 이동·확대·축소 후 `이 지역 검색` 버튼 노출**. 실제 검색은 버튼 탭 후에만 실행한다.
- **클러스터링(A) 승인:** 밀집된 여러 업체는 업체 수 숫자 핀으로 묶으며, 확대하면 개별 업체 핀으로 분리한다. **클러스터 탭(Q13 A)은 해당 군집 영역으로 지도 확대 후 `이 지역 검색` 표시. 자동 재조회 없음.**

## 2. 화면 레이어(위 → 아래)
1. Safe area와 상태 표시줄 아래 **헤더 오버레이**: 브랜드 `천하장사`, 기준 지역 표시(예: 아주대 주변), 알림 아이콘은 목업 요소이므로 실제 기능/화면 이동은 별도 정책 결정.
2. **검색창 오버레이**: 업체명 또는 품목 검색, 키보드 입력 중 지도 조작 방해 최소화.
3. **필터 칩 오버레이**: 식자재/소모품/배송 가능 등 목업의 시각 스타일 참고. 구체 분류/배송 조건은 API 가능 범위와 검토 후 확정.
4. **카카오 지도(WebView)**: 마지막으로 적용된 bounds의 **전체 일치 업체** 핀 및 밀집 업체 클러스터(업체 수), 기준 위치, 현재 위치 버튼. Android/iOS의 Safe area 고려. 목록 현재 로드 건수와 지도 전체 건수는 다를 수 있다.
5. **하단 드래그 시트**: 손잡이, 선택 카드 또는 업체 목록. 지도 위에서 올라오는 네이티브 UI.
6. **고정 하단 내비게이션**: 목업 상 5개(지도/AI 도우미/커뮤니티/저장/내 정보). 현재 코드는 4개(지도/AI 도우미/커뮤니티/내 업체)이므로 이번 화면 문서에서 5탭을 곧바로 구현 완료로 가정하지 않음.

## 4. 시트 상태 머신(제안)
| 상태 | 표시 | 주요 진입 이벤트 | 주요 이탈 이벤트 |
|---|---|---|---|
| `PEEK_SUMMARY` | 지도 중심 + 작게 접힌 전체 검색 결과 요약바/손잡이(최초 진입 **승인**) | 앱 진입 / 시트 접기 | 핀 탭(선택 카드), 위로 스와이프(목록) |
| `SELECTED_CARD` | 선택된 업체 요약 카드 | 핀 탭 | 다른 핀 탭(카드 교체), 위로 스와이프(목록), 아래로 스와이프(접힘) |
| `EXPANDED_LIST` | 현재 조건의 업체 목록 20개씩 추가 로딩, 선택 항목 강조 | 시트 위로 스와이프 | 아래로 스와이프(선택 카드 또는 접힘), 업체 행 탭 시 해당 업체로 지도 이동 + 선택 카드로 접기(Q15 확정), 다음 20건 로드 |
| `DETAIL_NAVIGATION` | 상세 화면 | 상세 보기 액션 | 뒤로 가면 지도와 유효 선택 유지(권장) |

- 지도 제스처는 WebView에, 하단 시트 제스처는 RN 네이티브 컴포넌트에 위임한다. 시트 위에서 지도 드래그가 발생하지 않게 분리.
- 선택 ID는 상태의 단일 원천. 재검색으로 선택 ID가 없어지면 선택 상태를 해제한다.
- 리스트의 각 행은 **마지막으로 적용한 지도 가시 영역 중심에서 가까운 순**으로 정렬된 전체 검색 집합 중 현재 로드된 20건 단위의 부분집합에 해당하는 업체 ID로 매핑한다. 지도의 전체 검색 대상과 목록의 **첫 20건**만 비교해 일치해야 한다고 요구하지 않는다. 지도에 좌표가 없는 업체는 핀을 임의 생성하지 않는다.

## 5. 화면 요소 → 데이터 매핑
| 요소 | 소스/변환 | 주의점 |
|---|---|---|
| 업체명 | `vendor.name` | 문자열 그대로 표시 |
| 업체 분류 | `vendor.category` | API가 지원하는 실제 분류값 확인 |
| 핀 위치 | `vendor.latitude`, `vendor.longitude` | 좌표 필수, 지도 WebView에 전달 |
| 업체 요약 품목 | `vendor.items[]` | 검색어와 품목명 부분 문자열 일치 필터링. 복수 일치 시 전체 일치 목록을 카드에 표시 |
| 가격 | 선택 품목의 `price`, `currency` | 업체 전체 최저가처럼 오인 금지 |
| 수량/규격 | `quantity`, `unit`, `specification` | 다른 규격 단순 가격 비교 금지 |
| 배송비 | `delivery_fee`, `delivery_fee_basis` | `null`은 무료 아님; `fulfillment`는 업체의 배송 제공 수준 |
| 확인일 | `checked_on` | 오래된 날짜 경고는 기존 SPEC의 AC06 준수 |
| 이미지 | `image_ids[]` 및 권한 검사 이미지 API | 없는 경우 플레이스홀더, 비공개 경로 노출 금지 |
| 거리 | `distance_m` | API가 내려준 경우만; 지도 기준점과 정확히 구분 |
| 출처 | `data_kind` 및 `source_type` | `live`와 시연 가격 구별 |

## 6. 핀 텍스트 상태 명세 (Q7=A 승인)

| 검색 상태 | 핀 레이블 | 승인 상태 |
|---|---|---|
| 검색어 빈 값 | `업체명` | 확정 |
| 품목명 검색, 해당 업체에서 일치 품목 정확히 1개 | `품목명 + 규격(있는 경우) + 가격` (예: `양파 10kg · 18,000원`) | 확정 |
| 업체명만 검색어와 일치, 품목 일치 없음 | `업체명` | 검색 결과 계약에서 유도 |
| 해당 업체에서 품목명 일치 2개 이상 | `일치 품목 N개` (가격 표기 없음) | **A 승인** |

- `query`는 이미 `GET /api/v1/vendors`에 존재한다. 하지만 그 결과 `vendors[].items[]`가 **검색어에 맞춰 필터링된 배열은 아닐 수 있다.** 실제 검색어와 품목명을 대조해 일치한 품목만 핀에 표기해야 한다.
- 검색어를 trim한 뒤 업체별 `items[].name`에 대해 대소문자 무시 부분 문자열 일치를 판정한다. 하나의 품목 ID는 한 번만 센다. 업체명 일치는 품목 수에 포함하지 않는다.
- 단일 일치: 핀에 품목명·규격·가격. **다중 일치: 핀에 `일치 품목 N개`만**; 선택 카드에 일치한 각 품목을 품목명·규격·수량/단위·가격으로 나눠 표시한다. 나열 순서는 기존 API의 품목 순서를 유지한다(가격순이나 최저가를 암시하지 않는다).
- 표시할 값은 `items[].name`, `specification`, `quantity`, `unit`, `price`, `currency`다. 가격이 없음/미확인인 시연 데이터라면 해당 사실을 표시하고 0원으로 대체하지 않는다.
- 지도 핀에 보여준 품목과 하단 선택 카드의 강조 품목이 같아야 하며, 서로 다른 가격을 보여서는 안 된다.
- `query` 변경·새 검색 결과 수신 시 이전 선택 품목·가격 레이블을 깨끗하게 갱신한다. **지도 조작만으로는 서버 결과를 바꾸지 않으며**, `이 지역 검색`을 눌러 결과가 갱신되면 마커·카드가 새 결과에 동기화되어야 한다.
- 현재 카카오 지도 페이지는 기본 `Marker`만 생성하고 WebView 전달값의 vendor에 `id/name/latitude/longitude`만 요구한다. **목업형 가격 라벨을 위해 WebView 데이터 계약·커스텀 오버레이를 추가해야 한다.** 단, 서버 API 응답/DB에 대표 가격 컬럼을 추가할 필요는 아직 없다.

## 7. 사용자 이벤트 상세
- 검색창 입력: 현재 `300ms debounce` 구현이 존재하나 최종 debounce 시간은 UX 점검 가능. 입력 중 하단 시트가 키보드를 가리지 않아야 함.
- 카테고리 변경: offset 초기화, 결과/핀/선택 상태 동기화.
- 핀 선택: 웹 페이지에서 `{type:'select',vendorId}`를 모바일로 전달. 모바일에서는 신뢰한 origin·현재 결과에 속한 ID인지 검사한 뒤 선택 카드 열기.
- 상세 보기: `/vendor/[id]` 라우트로 이동. 화면 진입 시 상세 API 호출.
- 시트 펼치기: 동일 검색 조건의 업체 목록 **20건 단위** 표시. 스크롤 하단의 추가 로딩(구체 트리거는 미확정)으로 다음 20건을 연결하고, 지도 전체 마커는 목록 페이지 추가 여부에 영향을 받지 않는다.
- 위치 버튼: 위치 권한 요청·허용/거부/실패 메시지 제공. 권한 거부 시 실제 위치인 것처럼 표시 금지.
- 지도 이동/확대/축소: 카카오 지도 조작 완료 후 `이 지역 검색` 버튼 노출(**승인**). 버튼 누르기 전에는 위치 관련 업체 검색 API를 재호출하지 않음. 눌렀을 때 지도 중심 등 현재 지도 상태를 읽어 검색(**현재 가시 화면 영역(bounds) 기준 확정 Q-SEARCH-07(A)**). 현재 `KakaoMap`은 중심/줌 변경을 RN에 보내는 이벤트가 없으므로 RN↔WebView 브리지 기능 추가 필요.

## 8. 로딩·빈 결과·오류 화면
| 조건 | 사용자 안내 | 동작 |
|---|---|---|
| 첫 조회 중 | 업체 불러오는 중 | 지도 및 로딩 상태 구분 |
| 검색 결과 없음 | 일치하는 업체가 없습니다 | 필터/지역 수정 유도 |
| API 오류 | 검색을 완료하지 못했습니다 | 재시도, 이전 데이터를 최신으로 속이지 않음 |
| 지도 실패 | 지도를 불러오지 못했습니다 | **목록은 계속 사용**; 지도 재연결 |
| 위치 거부 | 위치 사용 권한이 없어 기본 위치 표시 | 직접 위치 선택 가능 여부는 추후 설계 |
| 사진 없음 | 기본 썸네일 | 임의의 실제 업체 사진 사용 금지 |
| 데이터 미확인 | 가격/배송 조건 확인 필요 | 임의 0원 표시 금지 |

## 9. 시각 디자인
- 목업의 **주황 포인트 + 흰색 배경 + 검정 계열 텍스트** 기준.
- 상단 검색창: 둥근 흰 표면과 연한 그림자.
- 필터 칩: 활성=주황 강조, 비활성=흰/연회색.
- 업체 선택 핀: 주황색 강조와 터치 대상 구분; 구체 아이콘 크기는 디자인 시스템 토큰 승인 후.
- 카드: 흰 바탕, 둥근 상단 모서리, 끌어올리는 손잡이, 주황 CTA.
- 현재 소스 `colors.ink='#18283A'`는 남색 계열. **목업 목표인 검정 계열과 불일치**하므로 디자인 시스템 수정 대상으로 기록하며 임의로 코드를 즉시 바꾸지 않는다.
- 시트 크기/간격/애니메이션 속도는 기기별 안전 영역·접근성을 검증한 뒤 토큰으로 확정.

## 10. 접근성 / 기기별 사항
- 지도 핀, 필터, 시트 손잡이, 카드 버튼에 접근성 레이블. 지도 외 목록으로도 모든 업체 접근 가능.
- 스와이프가 어려운 사용자를 위해 시트 열기/닫기 버튼 대체 경로 제공.
- 하단 탭과 시트가 겹치지 않도록 safe area 반영.
- Android 뒤로 가기: 열린 시트 접기/상세 뒤로가기 동작 별도 테스트.
- WebView 지도 resize 시 relayout 및 상단 검색창/시트 오버레이 터치 영역 확인.
- 화면 작은 기기, 키보드 표시, 화면 회전 시 핵심 액션이 가려지지 않는지 확인.

## 11. 현재 코드와 차이(구현 에이전트 체크리스트)
- [ ] 현재 `Screen` + `ScrollView`로 나열된 지도/목록을 지도 풀스크린 + 오버레이 + 하단 시트 레이아웃으로 분리.
- [ ] 지도 핀 클릭이 현재 즉시 `/vendor/[id]`로 이동하는 동작을 **선택 상태 갱신**으로 변경.
- [ ] 하단 선택 카드와 스와이프 목록 구현 및 단일 선택 ID 연동.
- [ ] 현재 카카오 기본 마커를 목업형 라벨/선택 마커로 확장하려면 WebView 페이지·메시지 계약·테스트 함께 변경.
- [ ] WebView의 지도 조작 완료 이벤트를 RN으로 전달하고 `이 지역 검색` 버튼 가시성을 제어.
- [ ] 버튼 탭 때에만 현재 지도 위치로 재검색. 검색 범위는 가시 화면 bounds 기준으로 구현(구체 브리지/요청 계약은 승인 후 반영).
- [ ] 현재 4개 탭과 목업 5개 탭의 정보 구조 차이 별도 확정.
- [ ] 시연 자동 세션과 live/시연 데이터 경계는 인증/데모 명세에 종속; 이 화면 작업에서 권한 우회 금지.

## 12. UI 수용 기준
1. 앱 첫 화면은 지도 중심이며 검색/필터/하단 내비게이션이 지도 위 구조로 보인다.
2. 핀 탭 시 **상세 이동하지 않고** 업체 하단 카드가 열린다.
3. 선택 카드를 위로 펼치면 검색 업체 목록이 보인다.
4. 다른 핀을 탭하면 카드와 선택 상태가 해당 업체로 바뀐다.
5. 카드의 `업체 상세 보기`는 선택한 업체 상세 페이지로 이동한다.
6. 선택 카드·지도·목록은 같은 ID로 연결되고 재검색 시 잘못된 카드를 유지하지 않는다.
7. null 배송비·가격 미확인과 0원/무료를 혼동하지 않는다.
8. API 오류와 0건 결과와 지도 오류를 구분하고 지도 오류에서도 목록 이용 가능하다.
9. 검정 계열 텍스트와 주황 강조를 사용한다(정확한 HEX는 디자인 시스템 확정 후).
10. 모바일 기기에서 safe area, 접근성, 시트/지도 제스처 충돌을 테스트한다.
11. 검색 전 핀에는 업체명만 보이며, 단일 품목 검색 후에는 해당 품목·가격이 보인다.
12. 업체명만 검색된 결과에는 품목 가격을 임의 표기하지 않는다.
13. 검색어가 특정 업체의 품목 2개 이상에 일치하면 핀에는 일치 개수만 보이고 가격·대표 품목은 표시하지 않는다.
14. 위 핀을 선택하면 하단 카드에서 일치한 모든 품목의 가격·규격을 개별 확인할 수 있으며, 긴 목록은 시트 내 스크롤로 확인한다.

## 14. 지역 재검색 버튼 상세 명세 (Q-SEARCH-02 A 승인)
**상태 구분**
- `appliedSearchRegion`: 마지막으로 실제 검색 API에 사용한 지역 기준.
- `draftMapRegion`: 사용자가 조작한 현재 지도 화면의 중심 및 확대 수준 등.
- `regionSearchPending`: 두 기준이 달라 **사용자 재검색 동작이 필요한 상태**.
- 지도 드래그·확대·축소 조작이 종료되면 `regionSearchPending=true`로 전환해 지도 위에 `이 지역 검색` 버튼을 표시. 팬/줌 이벤트가 반복돼도 API 호출은 하지 않는다.
- 지도 처음 진입해 아직 조작하지 않았거나 마지막 검색 범위와 같은 경우 버튼은 보이지 않는다. 줌/중심을 되돌려 같아진 경우의 비교 허용 오차는 구현 과정에서 테스트로 확정.

**사용자 동작**
1. 지도를 손가락으로 이동하거나 확대·축소한다.
2. 사용자가 조작을 마치면 지도 상단의 검색창·필터와 겹치지 않는 위치에 `↻ 이 지역 검색` 버튼을 보여준다. 정확한 위치·여백은 디자인 시스템에서 조정.
3. 사용자가 버튼을 누르면 현재 지도 중심과 (검색 범위 정책 확정 후) 필요한 지도 상태를 기반으로 업체 목록을 다시 요청한다. 검색어/카테고리는 유지하고 pagination offset은 처음으로 돌아간다.
4. 새 결과 수신 시 지도 핀·일치 품목 레이블·시트 목록·선택 카드를 동기화한다. 선택 업체가 결과에서 제외되면 카드를 닫는다.
5. 로딩 중 반복 탭을 막고 오류가 나면 재시도 경로를 표시한다. 이전 결과가 남더라도 새 지역 결과라는 암시를 하지 않는다.

**구현 계약(에이전트에 대한 기술 제안, 확정된 공개 API 변경 아님)**
- 현재 `apps/cheonhajangsa/app/mobile-map/page.tsx`는 `ready`, `select` 메시지를 보내고 RN에서 `vendors`, `zoom`을 보낸다. 현재 **지도 이동 상태 이벤트가 없으므로 브리지 확장이 필요하다**.
- 제안: 지도 조작 완료 시 WebView→RN 메시지 `{type: 'viewportChanged', center: {latitude, longitude}, level: number}`를 보내고, RN에서 중심/줌을 검증해 버튼을 노출한다. 실제 메시지 구조는 UI·프론트 에이전트가 테스트와 함께 확정.
- 사용자가 지도에서 움직인 뒤 RN이 이전 검색 중심으로 지도를 자동 되돌리지 않게 **검색 기준점과 현재 표시 지도 중심을 별도 상태**로 보관한다.
- `GET /api/v1/vendors`는 현재 좌표+반경 검색. **사용자 A안에 따라 현재 화면 가시 bounds 검색으로 확장해야 한다.** 새 엔드포인트 필요 여부·Query 구조는 API 계약에서 확정한다.
- 카카오 지도 오류 시 지도 조작 버튼이 없어도 기존 업체 목록은 이용할 수 있어야 한다.

**테스트**
- 드래그 종료 시 버튼 표시 / 자동 검색 호출 없음.
- 줌 인·줌 아웃 시 버튼 표시 / 자동 검색 호출 없음.
- 버튼 탭 시 단 한 번의 지역 검색 요청, 연속 탭 시 중복 요청 방지.
- 검색 결과 도착 순서 역전 시 이전 지역 응답이 최신 지역을 덮어쓰지 않음.
- 지역 검색 실패 시 오류 표시 및 재시도.
- 시트와 검색창·필터 및 하단 탭이 버튼과 겹치지 않음.

## 15. Q-SEARCH-07(A) — 화면에 보이는 지도 영역 검색
- 사용자가 드래그 또는 줌 조작 후 `이 지역 검색`을 누르면 **현재 카카오 지도의 보이는 화면 bounds**를 사용한다. 고정 3km 원형 검색을 적용하지 않는다.
- 지도 중심이 같더라도 줌 수준이 다르면 조회 영역이 달라야 한다.
- WebView에서 지도 경계값을 얻어 RN으로 전달하는 메시지 계약이 추가 필요하다. 임의로 bounds를 추측하거나 이전 `center/radius` 값으로 대체하지 않는다.
- 검색어와 분류는 유지하고, 목록 페이지는 처음부터 시작한다. 성공 시 핀·선택 카드·목록을 동일 결과로 갱신한다.
- UI 시각 표현: 검색 전 결과를 새 지역 결과로 오해시키지 않도록 `이 지역 검색` 버튼과 이전 조회 적용 범위 상태를 분리한다.
- **열린 설계:** 하단 시트에 가려진 지도 영역을 포함할지, 매우 넓은 줌에서 어디까지 허용할지, 20건 이상일 때 목록과 핀을 어떻게 처리할지.
- **수용 기준:** 새 지도 중심/줌에 대응하는 bounds가 사용되며, 화면 밖 업체는 '현재 지도 검색 결과'에 포함되지 않는다.

## 16. 클러스터링 UI 명세 — Q-SEARCH-10(A) 승인
- **개별 핀:** 서로 떨어진 업체 또는 확대 결과로 분리된 업체에 표시. 레이블은 검색 전 `업체명`, 단일 품목 일치 `품목+가격`, 다중 일치 `일치 품목 N개`를 따른다.
- **클러스터 핀:** 인접한 둘 이상의 업체를 묶어 해당 **업체 수**를 숫자로 표시한다. 여러 업체의 가격을 하나로 합쳐 쓰지 않는다.
- **줌 반응:** 확대 시 클러스터 재계산 후 분리 가능한 업체는 개별 핀으로 노출. 축소 시 다시 클러스터로 합쳐질 수 있음. 이 화면상의 재배치는 서버의 `이 지역 검색` HTTP 요청과 분리된다.
- **선택/시트(Q13 A 확정):** 단일 업체 핀 선택은 하단 선택 카드로 연결. **숫자 클러스터 탭은 해당 군집에 맞춰 지도 중심을 이동·확대**한다. 목록·업체 선택 카드는 자동으로 열지 않는다. 확대 뒤 `이 지역 검색` 버튼을 노출하며 사용자가 누르기 전 위치 검색 API는 호출하지 않는다.
- **원천 ID:** 마커 중복 없이 동일 조회결과의 vendor ID로 묶는다. 클러스터 숫자가 조회에서 누락된 업체까지 포함한 전체 수인 것처럼 표시하지 않는다.
- **성능:** 지도 전체 결과 조회는 승인되었고 목록은 20건씩 추가 로딩한다. 단, 전체 조회의 구현 방식·상한 및 클러스터 알고리즘은 별도 설계 승인을 받는다. 기존 `WebView`는 Marker만 지원하므로 변경 필요.
- **테스트:** 밀집 업체 n개 → 업체 수 n 표시, 확대 후 분리, 품목 수와 업체 수의 혼동 없음, 클러스터 노출 중 네트워크 재검색 없음, 선택 카드 ID 일치, 로딩 및 지도 오류 시 대응.

## 17. Q-SEARCH-11(A) — 전체 지도 결과 + 목록 20건씩 추가 로딩
**사용자 승인:** 검색을 적용한 마지막 bounds에 일치하는 전체 업체 ID를 지도 핀 및 클러스터링의 대상으로 삼고, 하단 업체 목록은 20개씩 나눠 불러온다.

### 화면 데이터 상태
- `mapVendorSet`: 마지막으로 적용된 검색 조건의 **전체 업체 집합**. 지도 및 클러스터 계산의 유일한 원천.
- `listItems`: 같은 검색 조건으로 현재까지 로드한 **20건 단위의 목록 페이지 누적 배열**. `listItems`는 `mapVendorSet`의 부분집합일 수 있다.
- `appliedSearchKey`: 마지막 성공한 검색의 bounds/검색어/카테고리/출처를 묶는 키. 지도·시트·목록이 서로 다른 키의 데이터를 섞지 않는다.

### 화면 동작
1. `이 지역 검색`으로 검색이 완료되면 지도는 전체 매칭 업체를 표시하고 목록은 첫 20건부터 보여준다.
2. 시트를 위로 펼치면 처음 20건을 볼 수 있고 추가 로딩으로 21~40, 41~60 ...을 이어서 본다. 구체적으로 스크롤 도달 자동 로드 vs `더 보기` 버튼은 아직 미확정.
3. 더 많은 목록을 읽어도 지도 핀·클러스터의 업체 ID 총합은 변하지 않는다. 클러스터에 표시한 수치는 부분 목록 건수로 계산하지 않는다.
4. 지도 조작만으로 적용된 데이터 집합을 바꾸지 않는다. 화면 확대·축소에 따라 기존 전체 업체의 클러스터 배치만 다시 계산한다.
5. 새 검색 후 구 검색 페이지 요청이 늦게 도착하더라도 현재 목록·지도에 합치지 않는다.
6. 대량 조회가 아직 완전하지 않을 때 '전체 업체 수'로 단정하지 않는다. 완전성 확인 / 로딩 / 결과 과다 대응의 세부 UI는 조회 상한 정책 확정 후 설계한다.

## 18. Q-SEARCH-12(A) — 목록 기본 거리순 표시
- 기본 정렬 레이블은 `거리순`으로 표시한다(정렬 변경 컨트롤의 노출 및 다른 정렬 종류는 미확정). 기준점은 **마지막으로 검색을 적용한 지도 화면 중심**이다.
- 펼친 시트의 업체 목록은 해당 중심에서 가까운 순으로 배치한다. 동일 검색에서 목록을 20개씩 추가 로딩하는 동안에도 기존 행과 새 행을 통합한 **전체 거리순**을 보존한다.
- 사용자가 지도를 이동하기만 했을 때 목록은 재정렬하지 않고 `이 지역 검색` 버튼만 표시한다. 사용자가 눌러 새 조건을 성공 적용하면 중심을 바꾸고 목록을 첫 페이지부터 다시 표시한다.
- 별도 거리 표기(예: `350m`, `1.2km`)는 실제 거리 계산 결과가 확인될 때만 사용한다. 거리값이 없는 상태를 `0m`로 표시하지 않는다.
- **SEARCH-UI-AC34:** 초기 적용 중심에서 A 0.3km, B 1.1km, C 2.0km면 A→B→C 순. 지도만 이동했을 때 순서는 유지되고, 새 지역 검색 적용 후에는 새 중심 기준으로 갱신.
- **미결정:** 가격순 비교식, 페이지 커서/스냅샷, 시트의 정확한 노출 높이(px/dp; 화면 약 85% 목표는 확정), 클러스터 임계값 및 정확한 줌/애니메이션 사양.

## 19. 숫자 클러스터 탭 UI 명세 (Q13 A 확정)
### 이벤트/상태
1. `clusterPress(clusterVendorIds, clusterBounds)`는 **개별 업체 선택 이벤트(`select(vendorId)`)와 구분**한다. 해당 ID/범위는 마지막으로 적용한 전체 `mapVendorSet`에 근거한 유효한 클러스터여야 한다. 정확한 브리지 메시지 필드명은 구현 계약 승인 전까지 확정하지 않는다.
2. 탭하면 지도 WebView의 카메라가 해당 클러스터 영역으로 이동하고 **확대**된다. 목표 줌 레벨/애니메이션 시간과 경계 맞춤 정책은 후속 설계로 남긴다.
3. 새 줌에서 기존 지도 업체 집합에 대한 클러스터 계산을 다시 수행하고 분리 가능한 업체는 개별 핀으로 보인다.
4. 지도 조작 완료 시 `regionSearchPending=true`로 전환하여 **`이 지역 검색` 버튼**을 나타낸다. 탭·줌 이벤트만으로 검색 HTTP 요청을 만들지 않는다.
5. 사용자가 그 버튼을 눌러 현재 `draftBounds`로 재검색을 성공 적용한 뒤에만 `appliedBounds`, `mapVendorSet`, 하단 목록 1페이지 및 기본 정렬 중심을 갱신한다.

### 표시 및 접근성
- 클러스터의 접근성 역할은 버튼, 이름은 예: `업체 24곳 모임, 확대하기`. 클러스터 숫자는 **서로 다른 업체 ID의 개수**다.
- 개별 핀을 탭한 경우에만 해당 업체를 선택하고 하단 카드를 표시한다. 클러스터 탭만으로 선택 업체를 임의 지정하거나 하단 목록을 강제로 펼치지 않는다.
- 클릭 후 확대될 수 없는 최대 줌/겹치는 좌표의 처리 방식은 아직 미정이며, 임의 동작을 승인된 사양으로 만들지 않는다.

### UI 수용 테스트
- 밀집 클러스터 탭 → 지도 중심/줌 변화 → 클러스터 재배치 → 분리된 핀을 선택할 수 있음.
- 클러스터 탭으로 새 서버 업체 검색 요청 **0회**; `이 지역 검색` 버튼은 표시됨.
- 버튼 탭으로 새 가시 영역 재검색이 완료될 때만 하단 목록과 적용 검색 기준 중심점 변경.
- 단일 핀 선택 시에는 확대 동작 대신 기존 선택 카드 동작 수행.

## 20. Q14 A — 첫 진입 `PEEK_SUMMARY` 및 선택 카드(승인)
### 처음 화면
1. 로그인 화면 없이 지도 홈이 열리며, 하단 시트는 **작게 접힌 검색 결과 요약바** 상태로 시작한다. 업체가 자동 선택되어 있지 않다.
2. 요약바 구성: 드래그 손잡이, 검색 결과 개수(전체 수가 검증된 경우에만 `주변 업체 N곳`), 위로 펼쳐 목록을 확인할 수 있다는 안내/접근성 버튼. 구체 치수·문구 표현은 디자인 토큰 확정 전 초안이다.
3. 첫 조회 진행 중에는 결과 개수 대신 `업체 검색 중…` 등 로딩 안내를 사용한다. 검색 결과가 0곳이면 `검색 결과가 없습니다`. 실패하면 오류·재시도 상태를 표시한다. **목록 첫 페이지 20건을 전체 건수로 표기하지 않는다.**
4. 요약바를 위로 스와이프하면 `EXPANDED_LIST`(거리순, 20건 단위 추가 로딩)를 연다. 스와이프 대신 누를 수 있는 `업체 목록 보기` 경로도 둔다.

### 업체 핀 선택 후
1. 개별 업체 핀을 탭하면 **같은 하단 시트 내용**이 `SELECTED_CARD`로 바뀌고 선택 업체 정보를 보여준다. 탭만으로 상세 화면 이동·새 검색 요청은 발생하지 않는다.
2. 시트 카드에는 목업의 업체명·일치 품목·규격·가격·배송/확인일·`업체 상세 보기` 버튼을 사용한다(해당 필드가 확인된 범위에서만 표시).
3. 다른 개별 업체 핀을 누르면 같은 카드 위치에서 업체 정보를 교체한다. 시트를 위로 올리면 전체 업체 목록을 볼 수 있다.
4. 클러스터 탭은 Q13 A에 따라 지도 확대이며, 업체 선택 카드를 자동으로 열지 않는다.

## 21. Q15~Q24 일괄 승인: 상세 인터랙션

### 하단 시트 / 목록
- **첫 진입** `PEEK_SUMMARY` → 핀 탭 `SELECTED_CARD` → 위로 올리기 `EXPANDED_LIST` 기존 정책 유지.
- **Q15** `EXPANDED_LIST`의 업체 행 탭: `selectedVendorId` 설정 → 시트 `SELECTED_CARD`로 접기 → 업체 좌표로 카메라 초점 이동. 상세 페이지 자동 네비게이션 없음. 프로그램 카메라 이동과 사용자의 수동 지도 이동을 구분하여 **새 검색 API 자동 호출 금지**. 선택 업체가 현재 적용 결과에 없는 경우 접근하지 않음.
- **Q16** `EXPANDED_LIST` 목표 최대 높이는 화면 높이 약 85%; SafeArea/하단 5탭/키보드 표시 시 가용 높이 기준으로 조정한다. 시트 안에서만 목록을 스크롤하고 지도 드래그와 제스처 충돌을 방지한다. 정확한 dp 및 애니메이션은 디자인 토큰 단계에서 확정.
- **Q23** `SELECTED_CARD`에 `저장`(선택/해제) 및 `업체 상세 보기` CTA 두 개의 진입 경로를 제공. '저장'의 지속성은 로그인 화면 없이 개인 시연 세션 데이터로 분리한다.

### 검색창 / 필터 / 정렬
- **Q17** `draftQuery`(입력 중)와 `appliedQuery`(서버 검색 적용 값)를 분리한다. 키보드의 검색 버튼/제출 시에만 검색한다. 검색어가 달라지면 마지막 적용된 `appliedBounds`에 검색을 수행하고 결과·전체 핀·목록 20개·시트 선택을 동기화한다. 기존 Q8의 `이 지역 검색` 버튼은 **지도 영역 변화**에만 해당하며, 검색어 제출을 막지 않는다.
- **Q18** 필터 UI: 업체 유형, 품목, 배송 가능. 각 필터의 실제 데이터 경로/검색 조건은 API·DB 계약에 명시한다. 유효 배송 유형은 실제 DB 분류를 확인하고 **지역 배송 가능 여부를 자동 보장하는 것처럼 표기하지 않는다**.
- **Q19** 기본 거리순. **품목 검색이 적용된 상황**에서만 `가격순` 정렬 옵션을 노출한다. 가격순의 단위·규격·세금/배송료 포함 정책은 미결정이므로 계약이 확정되기 전 가짜 가격 비교를 표시하지 않는다.

### 첫 위치 / 빈 결과 / 데이터 표시
- **Q20** GPS 허용 시 현재 위치, 거부 또는 실패 시 아주대 주변 기본 중심. 예시 fallback `37.2834,127.0465`는 현재 `demoCenter` 코드값이며 실제 사용자 위치로 표시하지 않는다.
