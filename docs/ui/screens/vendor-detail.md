# UI-VENDOR-DETAIL-001 — 업체 상세 화면

- 상태: **정보 구조 및 기능 사용자 승인 / 세부 픽셀·토큰 초안**
- 진입: `지도 > 핀 선택 > 업체 상세 보기` 또는 별도 저장 목록·AI 추천에서 진입 가능하게 설계
- 기준: 사용자 목업의 흰색 배경, 검정 계열 기본 텍스트, 주황색 주요 행동 및 가격 강조

## 화면 계층 (위에서 아래로)

1. **상단 네비게이션**: `← 뒤로` · 제목 `업체 상세` · 우측 `저장` 토글. 스크롤 중에도 기본 복귀 가능.
2. **출처 안내**: 실제 승인 자료인지 시연/가상 정보인지 명확히 구분. 가상 데이터에 `시연용 가상 업체` 안내를 눈에 띄게 유지.
3. **업체 기본정보**: 업체명(주요 헤드라인), 업체 유형, 주소, 영업시간, 연락처, 설명(있는 경우), 업체 이미지(있는 경우).
4. **액션 영역**: `저장`(상단 토글과 같은 상태), `전화하기`, `지도에서 위치 보기`. 실제 주문/결제 버튼 없음.
5. **취급 품목 섹션**: 일치 품목 우선 → 나머지 공개 품목. 각 품목 카드: 품목명, 규격, 수량/단위, 가격, 세금, 최소 주문 단위, 배송비 및 배송비 부과 기준, 가격 확인일.
6. **거래/배송 조건**: `fulfillment`, `delivery_terms` 등 공개된 필드를 근거로 설명. 정보가 없으면 미확인 안내.
7. **하단 여백 / 안전 영역**: 시스템 홈 제스처·하단 네비게이션과 충돌하지 않도록 적응형 처리.

## UI 동작 상세

- 일치 품목 우선순위: 지도에서 적용된 검색어를 함께 전달받은 경우 그 검색어와 일치하는 품목을 먼저 나열; 이외 전체 품목도 볼 수 있어야 한다.
- 가격 누락: `가격 문의`; 배송비 누락: `배송비 미확인`; 영업시간 누락: `영업시간 문의`. 표시 문자열은 구현 단계에서 통일 가능하지만 **누락을 무료/0원으로 바꾸지 않는다**.
- 전화하기: 검증 가능한 연락처가 없으면 버튼 비활성 또는 명시적 안내. 가상 데이터에 임의 전화번호·업체 전화 연결 생성 금지.
- 지도에서 위치 보기: 지도 탭으로 돌아와 대상 업체에 카메라 초점을 맞추고 선택 카드 표시. 의도적 프로그램 이동에는 기존 `이 지역 검색` 수동 정책을 준수한다.
- 즐겨찾기: 저장 토글 상태는 다른 진입 화면과 동기화하며 게스트 개인 시연 세션에만 적용.
- 데이터 오류와 0건을 구분; 보안상 승인되지 않은 업체/내부 데이터 노출 금지.

## 내용 예시 (가상값; 실데이터 아님)

```text
← 업체 상세                                  ☆ 저장
[시연용 가상 업체]
아주 식자재
식자재 · 수원시 소재
영업시간: 정보 확인 필요
전화번호: 정보 확인 필요

[전화하기]  [지도에서 위치 보기]

취급 품목
┌ 양파 10kg ───────────────────────────────┐
│ 18,000원                                 │
│ 부가세 포함 · 최소 1박스 · 배송비 미확인     │
│ 가격 확인일: 2026-10-07                   │
└──────────────────────────────────────────┘

거래 조건
업체 등록 정보가 있으면 해당 내용을 표시
```

## 구현 체크리스트

- [ ] Safe Area 상단/하단 지원, 작은 화면에서 전체 내용 스크롤 가능
- [ ] 실제 승인 데이터/가상 시연 데이터 출처 구분
- [ ] 품목 정보의 명확한 단위 및 원화 표기
- [ ] 검색어 일치 품목 우선, 다른 품목도 유지
- [ ] 저장·전화·지도 이동 동작 연결, 중복 상태 없음
- [ ] 전화번호 없음/오류/비공개/네트워크 장애 대응
- [ ] 기존 5탭 앱 구조와 뒤로가기 흐름 일관성
- [ ] 접근성 버튼 이름 및 터치 목표 크기 확보
