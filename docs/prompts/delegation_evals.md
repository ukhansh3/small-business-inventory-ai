# 텍스트 Evals 러너 위임 기록

목표는 승인된 기존 텍스트 32건과 v3 파서를 비교할 수 있게 결과를 보존하는 것이다. [평가 설계](../../evals/EVAL_DESIGN.md)의 합격선과 기대값을 따르고, 기존 v2 기록을 덮어쓰지 않는다.

구현 범위는 고정 JSONL 입력, 기존 코드 채점기 재사용, 도구 형식과 허용 품목 ID 검사, 실행 정보와 실패 사례 기록이다. 실시간 모델은 CI에서 호출하지 않는다. 실행은 앱 폴더에서 `npm run evals`를 사용한다.

## 실제 기준선

[`v3` 결과](../../evals/results/2026-11-10T061130650Z_v3_claude-haiku-5-5.json)는 모델 `claude-haiku-5-5`로 텍스트 32건을 실행한 기록이다. 검색·단가 조건 일치는 21/22(95.45%), 형식과 범위 밖 분류는 각각 100%, 임의 생성·허용 밖 품목·호출 오류는 각각 0건이었다. 전체 케이스 31/32가 통과했고 사전 합격선을 충족했다.

실패한 `p06`의 입력은 “상추 3키로 얼마가 적당해요”다. 기대값은 수량 3kg과 금액 미상인 가격 진단이지만 모델은 판매처 검색을 선택했다. 동일한 기대값은 유지한다. 다음 개선 후보는 금액이 빠진 단가 질문과 일반 구매 검색을 구분하는 프롬프트 예시다.

기존 v2는 같은 입력·기대값과 모델 이름으로 22/22를 기록했다. 이전 결과에 카탈로그 해시가 없어 실행 환경의 완전한 일치나 프롬프트 변경의 인과는 확인할 수 없다.
