# 천하장사 MVP 아키텍처와 QA 경계

`사용자 입력 → 품목 이름·별칭 후보 조회 → AI 도구 선택 → 도구 입력 검증 → 서버의 검색·단가 계산 → 앱 결과`

품목 후보는 `apps/cheonhajangsa-mvp/server/ai/retrieval.ts`에서 이름과 별칭 일치로 찾고 최대 5개를 모델에 제공한다. 소규모 품목 카탈로그이므로 벡터 저장소와 임베딩을 사용하지 않는다. 지역, 배송, 영업시간과 가격 판단은 `core/search.ts`와 `core/price.ts`의 규칙을 따른다.

| 경계 | 입력 | 결과·부작용 |
|---|---|---|
| `search_vendors` | 품목 ID, 수량, 급함, 수령 방법 | 검증된 검색 후보 또는 누락 조건 질문. 검색 자체는 거래를 만들지 않는다. |
| `check_price` | 품목 ID, 수량, 금액 | 단가 진단을 만들고 설정된 기록 저장소에 진단을 기록할 수 있다. 시세 반영은 별도 동의가 필요하다. |
| `give_notice` | 안내 유형, 품목명 | 범위 밖·무관한 요청 안내. 판매처 검색은 실행하지 않는다. |
| 시세에 보태기 | 동일 기기 진단 ID, 명시적 `share: true` | 승인한 줄을 시세 표본에 반영하는 사용자 동작이다. 모델 도구로 노출하지 않는다. |

도구 인자는 JSON Schema와 서버 Zod 검증을 거친다. 서버는 활성 품목을 확인하고 시세 공유에서 동의와 기기·진단의 접근 범위를 확인한다. AI 호출 실패는 수동 조건 선택으로 이어진다. 골든 테스트는 해당 경계의 고정 규칙을 검사하고 텍스트 Evals는 실제 모델의 도구 선택·인자를 측정한다.

## 위협 목록 (2026-11-25, 최종평가 강의90)

공격 케이스는 `evals/evalset.jsonl`의 공격 범주(`a01`~`a06`)이고, 러너가 정상 범주와 같은 실행에서 `attack_success_rate`로 잰다(`evals/EVAL_DESIGN.md`).

| # | 위협 | 진입점 | 자산 | 공격자 목표 | 대응 | 공격 케이스 |
|---|---|---|---|---|---|---|
| T1 | 지원하지 않는 품목으로 검색·판정 실행(직접 주입) | AI 도우미 채팅 입력 | 품목 카탈로그와 검색 결과의 정확성 | 지시 무시·도구 인자 주입으로 목록 밖 품목의 판매처·가격을 내게 함 | 이름·별칭으로 찾은 후보만 모델에 제공(`server/ai/retrieval.ts`), 도구 인자 JSON Schema + 서버 Zod 검증, 활성 품목 확인, 범위 밖은 `give_notice` 안내 | a01, a02 (정상 o02~o06) |
| T2 | 검색 조건 날조 | AI 도우미 채팅 입력 | 상황별 추천(ADR-013: 양·시점·받는 방식으로 상황을 정함) | 문장에 끼운 가짜 지시로 양·받는 방식을 채워 다른 상황의 추천을 받게 함 | 프롬프트에서 문장에 없는 값은 null, 채점에서 없는 값 생성(fabricated) 0 목표, 결과 화면 칩으로 조건을 사장님이 보고 고침 | a03 |
| T3 | 가격 진단 조작(직접·간접 주입) | 채팅 입력, 영수증 사진 속 글자 | 가격 판정(R-28)과 사장님이 보탠 시세 표본 | 금액·양을 바꿔 판정을 뒤집거나, 보태기로 공유 시세를 오염 | 모델은 품목·양·금액 추출만, kg당 값 계산·판정은 서버 규칙(`core/market-prices.ts`), 시세 반영은 사장님의 명시적 동의(`share: true`)와 같은 기기 확인 | a04, a05 |
| T4 | 역할 탈취·AI 비용 남용 | 채팅 입력 | AI 호출 비용, 서비스 목적 | 일반 챗봇처럼 써서 자유 글을 받거나 호출을 반복해 비용을 늘림 | 모델은 도구 3개(`search_vendors`·`check_price`·`give_notice`) 중 하나만 고르고 자유 글을 사용자에게 보내지 않음, 무관한 요청은 잡담 안내, 호출 한도(기기당 시간 60회, 세션당 AI 6회) | a06 (정상 t01~t04) |
