# 천하장사 MVP 아키텍처와 QA 경계

`사용자 입력 → 품목 이름·별칭 후보 조회 → AI 도구 선택 → 도구 입력 검증 → 서버의 검색·단가 계산 → 앱 결과`

품목 후보는 `apps/cheonhajangsa-mvp/server/ai/retrieval.ts`에서 이름과 별칭 일치로 찾고 최대 5개를 모델에 제공한다. 소규모 품목 카탈로그이므로 벡터 저장소와 임베딩을 사용하지 않는다. 지역, 배송, 영업시간과 가격 판단은 `core/search.ts`와 `core/price.ts`의 규칙을 따른다.

| 경계 | 입력 | 결과·부작용 |
|---|---|---|
| `search_vendors` | 품목 ID, 수량, 급함, 수령 방법 | 검증된 검색 후보 또는 누락 조건 질문. 검색 자체는 거래를 만들지 않는다. |
| `check_price` | 품목 ID, 수량, 금액 | 단가 진단을 만들고 설정된 기록 저장소에 진단을 기록할 수 있다. 시세 반영은 별도 동의가 필요하다. |
| `give_notice` | 안내 유형, 품목명 | 범위 밖·무관한 요청 안내. 판매처 검색은 실행하지 않는다. |
| 시세에 보태기 | 동일 기기 진단 ID, 명시적 `share: true` | 승인한 줄을 시세 표본에 반영하는 사용자 동작이다. 모델 도구로 노출하지 않는다. |

도구 인자는 JSON Schema와 서버 Zod 검증을 거친다. 서버는 활성 품목을 확인하고 시세 공유에서 동의와 기기·진단의 접근 범위를 확인한다. AI 호출 실패는 수동 조건 선택으로 이어진다. 골든 테스트는 해당 경계의 고정 규칙을 검사하고 텍스트 Evals는 실제 모델의 도구 선택·인자를 측정한다.
